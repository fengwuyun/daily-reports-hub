# 一、Flowtica AI / Verso

## 1. 产品名称 & 一句话定位
**Flowtica AI**（产品 **Verso**）：一款厚度 6.5mm、重 78g、磁吸在手机背面的常显墨水屏 Agent 硬件，定位"以硬件为载体的个人上下文操作系统（Personal Context OS）"——不止录音转写，而是能记忆、能专注降噪、能把"记录"推进到"执行闭环"的随身 Agent 实体入口。

## 2. 产品定位与目标用户
- **解决的问题**：知识工作者的信息碎片化与注意力被切碎——会议、日程、待办、邮件、文档散落各处；录音转写/摘要正在变成"基础设施"、单点功能迅速同质化（创始人 Rian 原话）。
- **目标用户**（据科创板日报 / 网易）：企业管理者、高强度知识工作者、有专注需求人群。
- **形态取舍**：非对称屏幕布局 + 侧边实体键（FlowMark 标记重点、Ask AI 盲操提问），强调"保护专注力、保持在心流"，而非堆屏幕参数。

## 3. 核心价值主张
围绕 Personal Context OS 三层闭环（据硬氪首发 / 网易）：
- **Memory（记住什么）**：云端共享大脑把会议/日程/待办/邮件/文档串成连续长期记忆，而非一次性转写。
- **Attention（不被打断）**：常显墨水屏 + 磁吸 + 实体盲操 = 注意力降噪系统，无需解锁手机、不跳信息流。
- **Workflow Closure（事情真正做完）**：会前 Brief → 会中标记/转写 → 会后 Action Items 与跟进草稿，把"记录"推进到"执行"。
- 创始人判断：「真正拉开差距的，是谁能把分散信息串成一条连续的线，且随使用时间越用越值钱。」

## 4. 盈利与营收模式
- **硬件销售**：据 flowtica.ai 官网，Scribe（首款 AI 录音笔）硬件 $159、套装 $209；Verso 预订价 $199（零售价 $299，定金 $10；官网另见"Out Nov 17"预售文案，与"12 月量产出货"口径略有出入 → **不确定**具体发货月）。
- **AI 订阅**（关键营收点）：AI Plan 分 Free / Premium / Unlimited 三档；Free 含 Scribe 每月 300 分钟高级 AI 录音 + 有限 Ask Flowtica 额度；带 AI Plan 的套装 $278.99 / $328.99。
- **转化数据（最重要指标）**：首款 Scribe 海外众筹超百万元（CES 2026 创新奖、iF 2026 设计奖、$330K funded / 2000+ backers），2026 年初发货后常态化销售，**42% 硬件激活用户转化为订阅付费用户**（科创板日报 / ai.jp.net 均确认）。
- 收入结构：**硬件一次性 + 订阅复购**双轮，订阅是毛利与 LTV 主体。

## 5. 关键成本结构与资源
- **硬件 BOM 与供应链**：极致轻薄（6.5mm / 78g / 铝镁合金）对结构件、电池、墨水屏模组要求高；团队具备供应链能力（创始人十年硬件量产经验）。
- **云端大脑（Cloud-First）**：Personal Context OS 的 Memory/推理在云端，持续产生推理算力成本（与订阅毛利直接相关）。
- **数据与合规**：强调加密、SOC 2 审计进行中、不上第三方训练、不卖广告/数据中介——合规与信任是卖点也是成本。
- **人力**：硬核硬件 + 边缘 AI + 产品设计复合团队。

## 6. 获客与增长策略
- **众筹 + 展会预售**：Scribe 走海外众筹验证需求；Verso 在 IFA（9 月德国）宣发 + 定金预售，降低量产资金压力、提前锁客。
- **奖项背书**：CES 创新奖、iF 设计奖做信任与传播杠杆。
- **产品矩阵交叉**：笔（Scribe）/ 屏（Verso）/ 多端软件放进同一"一脑多终端"框架，短期办公矩阵、长期争夺办公信息入口。
- **政策顺风**：十五五规划、上海战略性新兴产业规划均点名端侧 AI / AI 终端，利好资本与渠道。

## 7. 竞争壁垒
- **供应链 + 量产经验**（李泽湘系 + Vimble 云台量产背景）—— 硬件创业最大死亡率在量产，这是硬门槛。
- **多端协同的产品矩阵**与"个人长期记忆资产"—— 用得越久越值钱，迁移成本高。
- **专注力产品设计哲学**（反参数内卷）—— 差异化定位，非单纯功能堆叠。
- **赛道卡位**：竞品逸文科技（累计销量数十万副）、Looki（>2 万台，年底预计 10 万）、灵络科技（AI 睡眠穿戴）已验证需求，Flowtica 以"Agent 闭环"切更高客单。

## 8. 可复刻该模式的关键步骤与所需条件
**低成本可起步部分：**
1. 先做**纯软件"个人上下文"App**（录音/笔记/日历/邮件接入 → 长期记忆 + 会前 Brief + 会后 Action），验证订阅转化，暂不碰硬件。
2. 用现成 LLM API + 向量库搭 Memory 层，MVP 成本极低（个人开发者可跑）。
3. 通过小红书/YouTube 展示"专注力工作流"差异化叙事获客，避开参数内卷。

**门槛高部分：**
4. 自研硬件需供应链、模具、认证、库存——资金与经验门槛高（建议众筹验证后再投入）。
5. "Personal Context OS" 要做到跨场景连续记忆，需长期工程积累与数据飞轮。
6. 合规（SOC 2 / 数据不出第三方）是 B 端/高端个人用户的信任前提。

# 二、Zeroset / Nebula

## 1. 产品名称 & 一句话定位
**Zeroset**（产品 **Nebula**）：把机器人领域的"world model（世界模型）"概念部署进企业，连接企业已有的办公/协作系统，捕捉"人 and Agent 跨系统工作时的状态与轨迹"，让 AI Agent 理解"工作到底是怎么一步步发生的"，从而自主完成任务——而非又一套文档搜索。

## 2. 产品定位与目标用户
- **解决的问题**：企业最贵的数据不是库里的字段，而是散落在邮件、工单、代码提交、IM 里的"工作实际怎么发生"；通用模型有知识截止、不懂企业内不成文流程与决策因果链（CEO Akshat Kannan 对 BI 原话）。
- **目标用户**：需要让 Agent **真正自主工作**的企业——减少手动写流程文档，让 Agent 理解"上次这类事是怎么审批/卡住/解决的"。
- **接入系统**：Microsoft 365、SharePoint、Outlook、Teams、GitHub 及职场沟通工具（据 RecodeX / 官方公告）。

## 3. 核心价值主张
- **时间维度 + 事件序列**：传统企业搜索/RAG 答"文档写了什么"；Nebula 答"上次这种事是怎么一步步做的"——建模决策、依赖、单公司特有的不成文流程。
- **world model 借壳**：机器人要先有"环境状态+动作如何改变状态"的表征，Zeroset 认为企业自动化缺的正是这种"表征工作并从中学习"的通用系统。
- **零手动流程文档**：输入是企业软件自然产生的行为轨迹，不要求员工手动写 SOP，降低数据准备成本。

## 4. 盈利与营收模式
- **定价：未披露**（pre-seed 阶段，官方未公布）→ **不确定**。
- **推断（基于 B2B SaaS 同类）**：大概率按席位 / 接入系统数 / 用量计费的企业订阅；也可能走"平台 + 实施"混合。需等 GA 后验证，本文不臆测具体数字。
- **当前阶段**：2026-01 成立，5 人团队，2026-10-06 出 stealth 并宣布 $5.2M pre-seed（co-led by Gradient、2048 Ventures，Leblon Capital 参与）。尚无营收披露。

## 5. 关键成本结构与资源
- **工程人力**：世界模型 / 跨系统轨迹建模是高智力密集，5 人极早期团队（创始人 18 岁 Stanford dropout、21 岁 UT dropout）靠技术密度而非规模。
- **集成与连接成本**：要覆盖 MS365/SharePoint/Teams/GitHub 等，连接器开发与维护是持续投入。
- **算力/存储**：持续捕获企业行为轨迹并建模，数据量与合规存储成本高。
- **信任与合规**：企业数据不出域、权限最小化是拿单前提（文中未明示其部署形态，标不确定）。

## 6. 获客与增长策略
- **概念差异化叙事**："把 world model 部署进企业"——用机器人领域成熟概念降维解释企业痛点，易获 VC 与早期技术买家关注。
- **早期靠 VC 背书 + 媒体**：Gradient（深度学习重镇）领投即信号；Business Insider 报道放大。
- **land-and-expand**：先接几个系统、跑通一个部门的工作流建模，再横向扩展。
- **冷启动难点**：需企业愿意开放系统权限与行为数据，销售周期与信任门槛高。

## 7. 竞争壁垒
- **"动态运营"建模的数据与集成深度**：能否覆盖企业关键决策系统、是否盲点少，直接决定模型价值。
- **概念先发 + 技术叙事**：在"Agent 真正自主"赛道占"运营世界模型"心智。
- **壁垒软肋（明确标出）**：
  - 若关键决策发生在未集成系统或线下沟通，模型有盲点（公司未披露如何处理）。
  - 价值强绑定数据质量与系统覆盖率。
  - 团队仅 5 人、极早期，执行力与留存是最大不确定项。
  - 传统企业搜索 / RAG 厂商与 Agent 框架随时可"加一层时间序列"跟进。

## 8. 可复刻该模式的关键步骤与所需条件
**低成本可起步部分：**
1. 选一个垂直场景（如"代码评审 / 工单流转"），用现成 LLM + 企业 API 拉取事件日志，先做"这件事上次怎么处理的"检索原型。
2. 用 RAG + 时间线重组即可验证"事件序列"价值，不必一上来造 world model。
3. 以开源/轻量部署卖给 1–2 家愿意开放数据的种子客户，拿真实轨迹。

**门槛高部分：**
4. 跨多系统的"状态—动作"世界模型需较强 ML 研究与工程能力。
5. 企业权限、合规、数据安全是拿单硬门槛，早期团队难独立扛。
6. 与 Microsoft / Atlassian 等原生生态竞争，需找到它们覆盖不到的"不成文流程"缝隙。
