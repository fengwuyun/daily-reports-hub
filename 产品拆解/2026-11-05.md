## 产品一：Serval — AI Agent 替换企业服务台（ESM/ITSM）

### 1. 产品名称 & 一句话定位
**Serval**——用 AI Agent 自动解决员工求助、把"工单队列"变成"对话即解决"的 AI 原生企业服务管理平台，定位为 ServiceNow 的替代系统（system of record），而非叠加层。

### 2. 产品定位与目标用户
- **解决谁的问题**：企业 IT、安全、HR、财务、法务、设施团队每天被大量重复内部请求淹没（密码重置、权限开通、入职/离职、设备申领）。传统 ITSM 只"记录工单等人手处理"。
- **目标用户**：CIO / IT / 安全 / 运维团队；从中大型科技企业起步（客户含 Lucid、Fox、WPP、Live Nation、Ramp，近半年新增 2 家 Fortune 20）。
- **源头**：CEO Jake Stauch 在 Verkada 时，客户希望"自动解决设备和网络问题"催生创意。

### 3. 核心价值主张
- **对话即解决**：员工在 Slack/Teams/邮件里说需求，Help Desk Agent 直接处置，不必进队列。
- **自然语言造工作流**：Catalyst（自动化 Agent）把"用大白话描述"变成**以代码形式落地的可审计工作流**，管理员审核批准后发布，每次运行有版本与历史。
- **关键设计点（卖点也是护城河）**：灵活 AI 前端 + 固定、可审计的后端动作分离——敏感操作（Okta 开通、Jamf 锁设备）需人工审批。安全/合规团队最看重这点。
- **已超出 IT 台**：2026-08 Catalyst GA 后，扩展到 HR/财务/法务/安全/设施，定位"全企业服务管理"。

### 4. 盈利与营收模式
| 项目 | 情况 |
|---|---|
| 定价策略 | **按报价（by quote）**，不公开价格；"一个平台费 + 由部署工程师主导的试点"（来源：VC Tracker / Serval 官网） |
| 收费结构 | 平台软件费 + ProServal 专业服务（>100 名自动化工程师驻场大客户，含 4 周培训的新毕业生为主）； buyers 需比较总实施/迁移成本、自动化率、持续服务费，而非单纯席位费 |
| 收入证据 | 官方称 "自 B 轮以来 ARR 每季度翻倍"——**无绝对值、未经审计，标不确定**；客户含 Lucid（45 天把 ITSM/CMDB/资产管理从 ServiceNow 迁至 Serval）、Fox、WPP、Live Nation、Ramp、2 家 Fortune 20 |
| 总融资 | $277M（$47M A 轮 Redpoint 2025-10；$75M B 轮红杉 2025-12 @$1B；$150M C 轮红杉 2026-10-29 @$3B） |

### 5. 关键成本结构与资源
- **算力/推理**：依赖底层大模型（官网集成 OpenAI 等），推理成本随用量上升——这是所有 Agent 厂商的共性风险点；Serval 自身毛利未披露（标不确定）。
- **人力**：重人力的部署/迁移——计划 12 个月内扩招 500+ 人（含 100+ 自动化工程师），在 NY/London/Austin 设办；员工数 12 个月涨 10 倍。说明"卖出 Agent 容易，接进客户真实流程贵且需人"。
- **合规资质**：SOC 2 / HIPAA / GDPR，SIEM 集成、审计日志——企业准入硬成本。
- **生态接入**：需对接 Okta/Google/GitHub/ServiceNow/Jira/Slack 等 30+ 系统，集成维护持续投入。

### 6. 获客与增长策略
- **冷启动**：从 IT 台单点切入（易量化 ROI：自动化率 >50%），再横向扩到 HR/财务/法务，制造"全平台替换"叙事。
- **渠道**：大客户直签 + 部署工程师驱动试点；红杉连续领投 B/C 轮带来背书与人才网。
- **裂变/口碑**：案例营销（Lucid 45 天迁移 ServiceNow）作为"可替代 incumbent"证据。
- **融资驱动**：一年三轮、估值 12 个月 3 倍，靠资本快速抢人抢客。
- **竞品对照**：ServiceNow（已 $2.85B 收购 Moveworks）、Atomicwork（$25M A 轮，走"先叠加后替换"低风险路线）、HelppliX（已拆，全渠道客服 Agent，定位不同）。

### 7. 竞争壁垒
- **系统记录层地位**：从"工单工具"升级为员工服务的统一系统，切换成本极高。
- **治理型架构**：AI 写代码工作流 + 人工审批 + Git 版本化，把"可控"做成卖点——这是企业敢用的前提。
- **部署深度**：ProServal 把交付人力变成护城河（客户迁移依赖 Serval 工程师）。
- **软肋**：ARR 绝对值/毛利/留存均未披露；生产可靠性与安全性需实战验证，融资新闻不解决。

### 8. 可复刻该模式的关键步骤与所需条件
**可低成本起步的部分（模式中抄）**
- ① 选一个高重复、低风险的内部流程（如权限申请/入职清单）做 MVP；
- ② 双 Agent 拆分：一个对话型接需求、一个"把自然语言转成可执行脚本/工作流"并强制人工审批；
- ③ 接 Slack/飞书 + 1–2 个系统（Okta/企微/钉钉）跑通"对话即解决"；
- ④ 用"自动化率"做付费钩子（按省下的人力小时或固定月费）。
- 1–3 人 + 现有 LLM API + 低代码/脚本即可起步，无需自研模型。

**门槛高的部分**
- 替换 incumbent（ServiceNow 级）需企业信任、合规资质、数十系统深度集成——非一日之功；
- 大客户迁移依赖重人力交付，规模化前毛利承压；
- 与通用 Agent 平台（如 WorkBuddy/Agent 生态）的差异化需靠"垂直流程 know-how + 治理"。

## 产品二：FuriosaAI — 推理专用 NPU 芯片 + NPUaaS

### 1. 产品名称 & 一句话定位
**FuriosaAI**——专注 AI **推理**的高能效 NPU（RNGD / "Renegade"）及配套软件栈与 NPUaaS，用"每瓦特更多 token、更低 TCO"对标英伟达 GPU 在数据中心推理场景的主导地位。

### 2. 产品定位与目标用户
- **解决谁的问题**：企业/云厂商推理成本高、功耗受限（机架功率密度卡在 15kW），需要不依赖液冷、能直接进现有机柜的高效推理硬件。
- **目标用户**：AI 云服务商、主权 AI 项目、AI 原生公司、自建/混合云企业；已落地 Samsung SDS（NPUaaS）、LG 集团（EXAONE）、LG U+、Daum（AI 摘要）、Upstage（实时搜索摘要）、瑞典 15MW 数据中心、Equinix 里斯本。
- **成立**：2017 年首尔，CEO June Paik（ex-AMD/Qualcomm/Samsung），联合创始人 Hanjoon Kim；2025 年初据称拒绝 Meta ~$800M 收购。

### 3. 核心价值主张
- **专为推理设计**：训练一次、推理运行数十亿次，推理场景能效是生死线；RNGD 不做训练，只做推理，换取极致功耗比。
- **能效与密度**：180W 风冷 PCIe 卡，8 张组 NXT RNGD Server（4U/3kW/4 petaFLOPS FP8/384GB HBM3），称同卡数下吞吐追平 RTX PRO 6000、每千瓦用户数翻倍；无需液冷改造即可进标准机柜。
- **架构创新**：TCP（张量收缩处理器）架构，把"张量收缩"作为软硬件基本单元，编译器跨整模型优化、减少耗能的数据搬运。
- **可编程/易迁移**：OpenAI 兼容 API（furiosa-llm）、PyTorch 2.x、vLLM、ONNX 导入；已验证 gpt-oss 120B、LG EXAONE 236B、Qwen3 等前沿模型。

### 4. 盈利与营收模式
| 项目 | 情况 |
|---|---|
| 硬件销售 | 卖 RNGD 加速卡 / NXT RNGD Server；2026 量产 2 万张、2027 年计划 >4 万张（TSMC 5nm + SK hynix HBM3） |
| NPUaaS 订阅 | 与 Samsung SDS 推韩国首个 NPUaaS，按 1/2/4/8 卡灵活按需订阅，企业免自管硬件——**这是最贴近 OPC 可借鉴的"算力即服务"形态** |
| 软件/生态 | SDK/编译器免费开放（吸引开发者、降低迁移成本），靠硬件与云消耗变现 |
| 营收目标 | 韩媒称 2026 财年目标营收约 1,000 亿韩元（约 $7–8 千万美元），已掌握 PO 约 200 亿韩元——**为媒体/公司目标口径，实际营收未公开审计，标不确定** |
| 最新融资 | $620M D 轮（2026-10-28），$2.9B 投后估值（较此前 $735M 翻约 4 倍）；韩国成长基金 $280M 领投、国际 $110M（Infinitum 最大国际投资方、Jericho/Worldline/QUDA/NeoFort/Cisco）、老股东 $125M（NAVER/KDB/DSC/Nextrans/Kakao）；进出口银行首次直投初创、UAMCO $30M、韩华 |

### 5. 关键成本结构与资源
- **重资产前置**：芯片设计 + TSMC 流片 + HBM3（SK hynix）绑定 + 量产良率——资本极度密集，本轮 $620M 大部分用于扩产与 Gen3 研发。
- **软件栈投入**：约 200 名工程师中 2/3 是软件（编译器/SDK），Lisbon 设编译器研发实验室——印证"竞争力从硬件转向软件"。
- **生态合作**：与 Broadcom 合作开发 Gen3（台积电 2nm + HBM4，目标 2028 出样）；与 Samsung SDS/Equinix 做交付与区域落地。
- **主权/政策资源**：韩国成长基金、进出口银行等国资入场，绑定"国家 AI 半导体自主"叙事（对标中国算力自主）。

### 6. 获客与增长策略
- **标杆客户先行**：用 Samsung SDS（NPUaaS 落地）、LG（EXAONE 生产部署）做参考架构，降低其他企业导入顾虑。
- **主权 AI 切入**：韩国/欧盟（Equinix 里斯本，规避 Cloud Act  jurisdiction）等强调数据主权与能效的市场。
- **软件降摩擦**：OpenAI 兼容 API 让客户"几乎不改代码"迁移，对抗 CUDA 锁定。
- **区域扩张**：设新加坡枢纽推 APAC，目标 2027–2028 IPO（Morgan Stanley / Mirae 联席顾问，此前寻求最高 $500M pre-IPO）。

### 7. 竞争壁垒
- **架构能效（TCP）**：差异化于 matmul 固定指令的 GPU，数据搬运能耗更低。
- **软件栈成熟度**：compiler-first，已验证前沿开源模型规模推理，非仅 benchmark。
- **政策 + 资本**：韩国国家级资金与主权叙事，构筑区域护城河。
- **软肋（明确标注）**：CUDA 十五年生态难替代，每个新工作负载仍需专门移植；客户重复下单意愿存疑（韩国同业 Rebellions/DeepX 同样卡在量产商业化）；能效对比多为**厂商自测基准（标不确定）**；实际营收规模远小于融资声量。

### 8. 可复刻该模式的关键步骤与所需条件
**可借鉴的思路（低成本可学）**
- ① 定位"推理专用"而非"通用"——卖 TCO/每瓦特 token，不卷峰值 FLOPS；
- ② 做"OpenAI 兼容 API 层"降低客户迁移成本，用软件对抗生态锁定；
- ③ 推**按卡数订阅的 fractional NPUaaS**（1/2/4/8 卡）——这一云服务形态任何加速器供应商（含国产卡）都能抄，是中小团队切入"算力即服务"的低成本路径；
- ④ 借"主权 AI/数据不出境"区域叙事拿政策与首批客户。

**门槛极高的部分**
- 自研芯片：fab（TSMC）、HBM 供应、流片与量产资金——非 $620M 级资本不可为；
- 编译器与全栈软件工程人才密度（2/3 软件工程师）；
- 与英伟达 CUDA 生态正面竞争，需持续客户成功案例背书。

## OPC 视角可行动建议（给 Oscar / 一人公司）
1. **Serval 模式最值得抄骨架**：其"双 Agent（对话接需求 + 写可审计工作流 + 人工审批）+ 按自动化率收费"是 30 天拿第一笔收入的高契合模板。可迁移到你的垂直场景——例如把「海外短剧投放日常运营（权限/素材/账号批量操作）」或「一人公司财务/合同流程」做成对话即解决的 Agent，先服务自己再对外。
2. **别碰芯片，但学 FuriosaAI 的定价心智**：卖"推理效率/省下的钱"而不是"算力峰值"；若做 AI 工具，对外报价用「按结果/省时」而非「按 token/席位」，与系列前文 Broccoli/Omnichat/Duvo 的"按增量价值定价"一脉相承。
3. **fractional NPUaaS 思路**：如果未来要做"算力即服务"类小生意，优先做"OpenAI 兼容 API + 按卡/按时订阅"的轻运营层，而非自研硬件——用现成国产/海外加速器即可起步。
4. **共同警示**：两家都靠"大融资 + 大客户部署"讲增长，但 Serval 的 ARR 绝对值、FuriosaAI 的实际营收都未独立审计。做产品时，**先有可验证的付费证据再谈规模化**，正是你定的"30 天拿第一笔收入"纪律的反面教材参照。
