## 一、Wabi —— 多人共享的「生活操作系统」AI 助手

### 1. 产品名称 & 一句话定位

- **Wabi**（Wabi Inc.），创始人 Eugenia Kuyda（Replika 创始人，Replika 累计超 3500 万用户）。
- 一句话定位：**「你们一起用的 AI 助手」**——把 AI 嵌进群聊，按需生成小应用，让家人/朋友/小团队共享同一份计划与工具。

### 2. 产品定位与目标用户

- 解决谁的什么问题：主流个人助手是「一对一、单线程」，聊久了上下文堆积→幻觉、丢上下文、越权风险高；且**没人解决「多人协作场景下的 AI」**。Wabi 把生活按主题拆成「线程（thread）」，线程可变成群聊，一家人/情侣/小团队共享同一份日历、行程、待办、投票。
- 目标用户：需要共同规划生活的人——家庭、情侣、小团队（旅行、账单、学校、聚餐等）。
- 形态：即时通讯 App（iOS / Android / Mac 已开放，Windows 在规划）；2026-09-28 以「会做应用、替你和朋友办事的 messenger」重新发布，2026-10-19 全面开放、取消等待名单。
- 对照：Meta Muse 是「替你一个人干活」（后台异步、权限为核心资产），Wabi 是「在场边说边搭、把结果沉淀成可复用界面」（共享关系链为核心资产）。

### 3. 核心价值主张

- **多线程上下文隔离**：每个主题一个线程，避免单线程无限对话导致的幻觉与上下文丢失——这是 Kuyda 反复强调的架构优势。
- **Agent 自动搭应用**：连接邮箱后自动生成初始线程与 mini-app；用户也可随时要求生成（共享日历、行程地图、投票、追踪器、读书清单、甚至聊天内小游戏）。从 1.0「用户自己 prompt 造应用」演进到 2.0「Agent 替你决定造什么」。
- **多人共享**：线程即群聊，参与者看到同样的计划与工具；权限按聊天范围隔离，请求个人信息时全员可见（透明护栏）。
- **主动提醒**：连接 email/日历/联系人/位置/照片/健康数据后，主动标记账单、表格、待跟进事项；重要动作先问用户。
- **集成即行动力**：已接 Plaid（算预算、标记遗忘的自动续费）、Gmail（监控关键邮件提醒）；vibe coding 允许在聊天内造轻量应用/小游戏。

### 4. 盈利与营收模式

- **当前：完全免费**，三端均无内购（TechPilot 2026-10-24 核对 App Store / Google Play 确认）。
- **商业模式尚未确定**（Kuyda 公开表述）。潜在方向（基于行业与 Kuyda 产品观推断，**非公司确认**，标不确定）：
  - 付费订阅档（参考同类 Muse $20/$100 月）；
  - 交易/金融抽成（已接 Plaid，可能走「替你省钱/理财」抽成）；
  - 企业版 / 团队协作版；
  - 数据驱动的增值服务。
- 融资支撑：2025-11 $20M 种子前轮（a16z 领投）→ 2026-11 $55M 种子轮（IVP 领投，a16z、Forerunner、Amazon Alexa Fund 跟投，天使含 Marc Benioff、Tobi Lütke、Marissa Mayer），估值 $1.25B。

### 5. 关键成本结构与资源

- **推理算力成本（最大隐性成本）**：全免费 + 多线程 + 自动建应用 + 主动监控，意味着每个活跃用户都在持续烧 token；中文/阿拉伯语等 token 效率更低（多语言模型阿语比英语多耗 30–50%）。Wabi 未披露模型与单用户成本 → **不确定**。
- **模型依赖**：底层用 Google / Anthropic / OpenAI 模型（公司披露可能处理用户与连接数据），自身未训练专用模型 → 成本受第三方定价钳制，毛利承压。
- **人力/合规**：SOC 2 合规审计、US 云存储、隐私与权限设计。
- **数据资源**：Replika 积累的 3500 万级消费 AI 用户经验 + 12 年消费 AI 产品方法论。

### 6. 获客与增长策略

- **免费降门槛 + 名人创始人效应**：Kuyda（Replika）自带消费 AI 信任与媒体关注；TechCrunch Disrupt 站台、密集科技媒体覆盖。
- **平台铺开**：iPhone-only 邀请制 → 6 周后 Android → Mac → 全面开放，快速扩大可下载面。
- **多人裂变天然性**：群聊产品本身带社交传播——拉家人朋友进线程即获客。
- **融资驱动冷启动**：靠大额种子轮支撑免费期的推理成本与增长，赌「先规模后变现」。
- **数据飞轮（预期）**：免费换真实场景对话/使用数据，再据此设计付费层。

### 7. 竞争壁垒

| 壁垒类型 | 评估 | 说明 |
|---|---|---|
| 技术 | 中 | 多线程上下文隔离是真实架构差异，但非高不可攀；Agent 自动建应用属工程实现 |
| 数据/关系链 | 高（潜在） | 多人共享的群聊关系链与共享上下文，具有网络效应与切换成本 |
| 品牌/创始人 | 高 | Kuyda + Replika 背书，消费 AI 赛道先发认知 |
| 合规 | 中 | SOC 2 + 按聊天范围权限隔离；但下游数据处理披露少（标不确定） |
| 生态 | 低-中 | Plaid/Gmail 等集成可复刻；无独家生态 |

- Kuyda 自述「没人真正解决过多人问题」——**多人共享是它押注的品类级壁垒**，但需先证明用户愿意让 AI 介入群聊。

### 8. 可复刻该模式的关键步骤与所需条件

**可低成本起步的部分：**
1. 选一个「小群体协作」细分场景（家庭账本、情侣旅行、小团队待办），而非做通用助手。
2. 用现成大模型 API + 一个线程/群聊框架，实现「对话即生成小工具」（参考其 mini-app-in-chat 模式）。
3. 按聊天范围做权限隔离 + 重要动作二次确认（安全护栏，成本低但用户感知强）。
4. 免费冷启动，靠社交裂变获客。

**门槛高的部分：**
- 名人创始人带来的信任与媒体杠杆（不可复制）。
- 长期免费所需的融资能力与算力成本承受力（预营收阶段烧钱）。
- 多线程架构在规模下的稳定性与成本优化（需工程积累）。
- 让用户在预营收产品上连接银行/邮箱的信任门槛。

**落地清单（单人/小团队可做的 MVP）：** 一个「家庭/小团队共享待办+日历」的微信小程序或群机器人，Agent 根据聊天自动建清单/投票，免费跑通留存，再考虑订阅或轻交易抽成。注意：**金融账户连接务必后置、用持牌集成（如 Plaid 类）**，不要自己碰资金。

## 二、Collective —— 面向「一人公司」的 Agentic 财务 OS

### 1. 产品名称 & 一句话定位

- **Collective**，创始人 Hooman Radfar（连续创业者，AddThis 被 Oracle 收购，Expa 合伙人），2020-09 公开上线。
- 一句话定位：**「一个人也能用上世界级的财务部门」**——把公司注册、记账、开票、发薪、报税、保险、支持打包成一个 AI 自主运行的财务操作系统，专服务「一人公司（Business-of-One）」。

### 2. 产品定位与目标用户

- 解决谁的什么问题：美国约 3000 万「非雇主企业（solo business）」没有财务部，靠拼凑多款软件 + 高价 CPA 处理记账/报税/发薪，随收入增长后台成为瓶颈、还漏掉税务优化。Collective 用 AI + 金融基础设施「在后台自主预判、协调、执行」财务流程。
- 目标用户：自由职业者、顾问、独立专业人士、无专职财务团队的个人创业者（Stripe 数据：2023–2025 年年收入 $1M 的个人运营者翻倍、$10M 的三倍）。
- 功能矩阵：公司设立（LLC 等自动注册）→ 记账（分类+对账）→ 开票 → 发薪（S-Corp 薪资优化）→ 税务（自主申报+持续优化）→ 商业保险 → 健康保险 → 支持（人+AI，50% 工单自主解决、4.5 星）。

### 3. 核心价值主张

- **全栈整合 vs 拼凑工具**：不是再给一个会计软件，而是把「设立—记账—开票—发薪—税—保险」收进一个平台，减少在多家服务商间切换。
- **AI 自主执行**：费用分类、对账、税务申报与优化等流程后台自动跑，用户不被软件「反操作」。
- **税务省钱（最硬的价值证明）**：公司口径称累计帮用户省税约 $3.5 亿，高收入会员年省最高 $4 万；人均年省约 80 小时。→ **均为公司自报、未独立审计，标不确定**。
- **AI+人混合支持**：AI 自主解决 50% 工单，保留人类专家兜底，4.5 星满意度。

### 4. 盈利与营收模式

- **订阅制**：LLC 方案 $199/月；S-Corp 方案 $349/月（valueaddvc 披露）。
- **收入结构**：会员订阅为主；扩张方向含银行与保险（通过合作机构，具体产品未披露 → **不确定**）。
- **融资结构亮点**：本轮 $100M = $40M Series B（股权，General Catalyst / QED / Gradient 领投，Intuit Ventures、FT Partners、SemperVirens 跟投）+ $60M 增长设施（General Catalyst 客户价值基金，按所获客收入挂钩、用于买量而非稀释股权）。这种「股权 + 收入挂钩增长贷」结构值得中小垂直 Fintech 借鉴。
- 历史融资：2021-05 $20M A 轮（GC+QED）；2023-07 $50M（累计 $82M）；本轮后累计约 $182M。

### 5. 关键成本结构与资源

- **获客成本（CAC）**：靠 $60M 增长设施集中买量；单位经济（unit economics）被 General Catalyst 点名「高质量」→ 但 ARR 绝对值、客户数、利润率均未披露，**独立评估困难（标不确定）**。
- **合规/牌照资源**：税务、保险、发薪涉及强监管，需专业资质与合规体系——这是核心资源壁垒。
- **人力**：人类专家（CPA/保险）兜底，AI 替代一半工单 → 人力成本随规模边际下降。
- **金融基础设施**：银行/保险需对接合作机构，自建门槛高。

### 6. 获客与增长策略

- **精准细分 + 强价值锚**：锁定「一人公司」这个被大 Fintech 忽视、却约 3000 万规模、近 $2 万亿营收的利基。
- **税务省钱作为买点**：用「最高年省 $4 万」「累计省 $3.5 亿」等具体数字做转化（公司口径）。
- **增长设施买量**：用收入挂钩资金做规模化获客，股权不被过度稀释。
- **口碑/案例**：设计师等真实用户证言（S-Corp 设置年省数万）。
- **扩张路径**：从纯 solo 延伸到「有雇员的公司」，并向银行/保险做全栈金融延伸。

### 7. 竞争壁垒

| 壁垒类型 | 评估 | 说明 |
|---|---|---|
| 技术 | 低-中 | AI 自动化工作流可复刻，非技术壁垒 |
| 数据/合规 | 高 | 税务/保险/发薪的合规能力、专业资质、审计可信度 |
| 信任/品牌 | 高 | 财务托管场景，信任是首要门槛；多年沉淀 |
| 切换成本 | 高 | 财务/税务/银行全栈绑定后迁移成本高 |
| 生态/牌照 | 高 | 银行/保险合作与牌照资源，新进入者难短期补齐 |

- 软肋：ARR、客户数、利润均不透明；银行/保险扩张的具体形态与是否自营未定（标不确定）。

### 8. 可复刻该模式的关键步骤与所需条件

**可低成本起步的部分（给 Oscar 的 OPC 视角）：**
1. **概念可抄**：把「一人公司/自由职业者的后台」做成「AI 托管服务」而非「又一个软件」——关键在「替用户把事办了」而非「给用户更多工具」。
2. **轻量 MVP（中国语境）**：针对国内个体户/自由职业者，做「注册+记账+报税提醒+社保/商业保险对接」的轻量托管助手，先从信息聚合与提醒（低风险）做起。
3. **AI+人混合**：先用 AI 处理 50% 标准化工单，人类专家兜底，控制人力成本。
4. **按结果/订阅收费**：参考 $199/$349 月档，结合国内客单价做本土化定价。

**门槛高的部分：**
- 税务/保险/发薪的**牌照与合规资质**（中美皆强监管），是根本门槛，不能裸奔。
- 银行/支付/保险的**持牌合作渠道**资源。
- 规模化后的**信任与审计体系**（财务数据的误判有法律后果）。

**落地清单（若 Oscar 想做中国版「一人公司财务 OS」）：** 先以「AI 财税助手（纯咨询/提醒，不碰资金）」小程序验证需求与付费意愿 → 再逐步接入持牌代账/保险合作方 → 订阅制收费。务必把「合规边界」写进产品首屏，避免越界做无资质金融服务。

## OPC 视角可行动建议（给 Oscar）

1. **Collective 教的是「把后台服务变成 AI 托管」**：Oscar 的 OPC 一人公司场景，最缺的就是财务/行政后台。可先做一个「中国个体户/自由职业者 AI 财税助手」MVP——纯提醒+聚合+对接持牌方，验证「30 天拿第一笔收入」的订阅付费意愿，比直接做通用 Agent 更聚焦、更合规。
2. **Wabi 教的是「共享式主动智能」的产品形态**：其「线程=群聊=可复用小应用」的结构，对 Oscar 的短剧/微信生态团队协作、乃至家庭账本类小程序都有借鉴——**交付物是「留在那儿能接着用的界面」而非「一次性执行结果」**，这个产品哲学值得记。
3. **两条的共同底层**：AI 正把「团队/部门能力」压缩给个人。Oscar 做方向选型时，优先选「替一类人把后台/协作办了」的托管型产品，而非「再给一个工具」——前者付费意愿与留存都更强（Collective 的 $199/$349 月 vs Wabi 的免费困境就是对照）。
4. **风险对照**：Wabi 的「预营收 + 全免费 + 烧推理成本」是高风险赌注；Collective 的「订阅+清晰省钱价值」是更稳的变现范本。OPC 早期应学 Collective 的「先有付费证据再扩张」，避免 Wabi 式长期烧钱。
