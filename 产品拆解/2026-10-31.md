# 产品一：Greptile — AI 代码审查 Agent

## 1. 产品名称 & 一句话定位
**Greptile**：在完整代码库上下文中自动审查并测试每个 Pull Request 的 AI Agent，定位为「所有代码改动的统一独立验证层」。

## 2. 产品定位与目标用户
| 维度 | 内容 |
|---|---|
| 解决谁的问题 | 工程团队在 AI  coding 提速后，**代码审查成为新瓶颈**；人类 reviewer 容易漏掉跨文件逻辑 bug、被 AI 生成代码的「看起来很对」误导 |
| 目标用户 | GitHub/GitLab 上的工程团队（从开源项目到 Nvidia、Coinbase、Brex、Meta PyTorch、Retool、Zapier 等）；强监管行业（国防/医疗/金融）走自托管企业版 |
| 切入点 | 不读 diff  alone，而是先建**全仓库语义图**（函数/类/import/commit 依赖），再派 swarm of agents 跨文件推理 |

## 3. 核心价值主张
- **跨文件逻辑 bug 捕获**：传统 linter/LLM 读 diff 抓不到的「破坏调用点、遗漏分支、契约不一致」，Greptile 靠全仓库图 + 多跳推理识别。
- **TREX 真实跑测试**：在沙箱里实际执行 PR 分支，捕获只在运行时出现的回归——不止静态分析。
- **持续学习团队规范**：读团队历史 PR 评论，吸收「接受/驳回/改写」模式，噪声随时间下降；规则可用自然语言写。
- **充当「中央验证层」**：与 Claude Code / Cursor / Codex / Devin 等 coding agent 无缝协作（MCP、CLI、`/greploop`），统一兜底 AI 写的代码。

> 公司自报：自 2026-03 以来累计标记 1700 万条 issue，**过半是真实行为缺陷**（P0 严重 1% / P1 缺陷 52% / P2 质量 47%）；日审查 GitHub 超 1% 的 PR。上述为厂商口径，未独立审计。

## 4. 盈利与营收模式
| 档位 | 价格 | 关键内容 |
|---|---|---|
| Starter | 免费 | 1 名开发者、50 credits/月、无限仓库 |
| Pro | **$1 / credit，无席位费** | 无限开发者与 Agent；Base 审查 1 credit、Plus 3、Apex 10；credits 全组织共享 |
| Enterprise | 定制 | 自托管（含 air-gapped）、SSO/SAML、RBAC、GitHub Enterprise/GitLab Self-Managed 等、数据驻留 |

- **计费逻辑**：花销由「审查量 × 审查深度」驱动，而非工程人头——这是相对传统 per-seat SaaS 的关键差异。
- 开源项目免费、pre-Series A 创业公司大幅折扣（获客/口碑策略）。
- **收入/ARR 未披露**（官方 B 轮公告与 VCT 均确认未公开）→ 标不确定。
- 客户规模：官网称 **22,000+ 团队**使用；第三方 The AI Tool Bible 报道 **9,000+ 团队**（口径/时间差异，未独立核实）→ 标不确定。

## 5. 关键成本结构与资源
- **算力成本（核心不确定项）**：每次有用审查背后消耗多少 LLM 推理，官方未披露；这是 $750M 估值下必须回答的「审查毛利」问题。
- 工程：全仓库语义索引的构建与持续同步（大仓库初始索引耗时）。
- 合规：SOC 2 Type II（报告可向客户索取）；客户数据在管理员请求后 1 天内从生产系统硬删除；自托管满足监管数据不出租户。
- 底层模型栈**未公开**（营销页未披露），对强数据合规买家是隐患。

## 6. 获客与增长策略
- **PLG + 开源/创业公司免费**：降低试用门槛，靠口碑在 GitHub 自然扩散。
- **绑定 coding agent 生态**：MCP/CLI/插件让 Greptile 成为 Claude Code、Cursor 等的「验证后端」，借生态流量。
- **标杆客户背书**：Brex、Nvidia、Meta PyTorch 等 logo 驱动信任。
- **融资驱动品牌**：Benchmark（$25M A，2025-09）→ Menlo（$50M B，2026-10）连续加注，Deedy Das 入董事会。
- 近期 OpenAI 披露 Greptile 借助 **GPT-6 Astra 的 computer-use** 规模化自动化测试（腾讯快报 10/27，来源为 OpenAI 官网披露）→ 强化「大公司更高信心发布」叙事。

## 7. 竞争壁垒
- **技术深度**：全仓库语义图 + TREX 沙箱执行，是「LLM 读 diff」类竞品短期难廉价复制的护城河（hokai.io 评：CodeRabbit/Qodo 在缩小精度差距但噪声更高）。
- **网络/数据飞轮**：团队接受/驳回反馈持续训练，越用越准。
- **生态位卡位**：定位「独立验证层」，与 coding agent 互补而非竞争，避免被 agent 厂商内置功能吞掉。
- **软肋**：① 噪声/误报率曾在独立基准中居竞品前列；② 第二个 AI 可能复现第一个 AI 的错误；③ 模型成本与质量未透明。

## 8. 可复刻该模式的关键步骤与门槛
| 步骤 | 内容 | 门槛 |
|---|---|---|
| 1. 低成本起步 | 用开源 LLM（DeepSeek/Codex 类）+ 仓库 AST/依赖图，做「diff + 跨文件上下文」审查 bot，先打 GitHub App | **低**：单人或小团队可在数周内出 MVP |
| 2. 做深上下文 | 建全仓库语义索引 + 多跳推理，而非纯 diff 扫描 | 中：索引构建/同步有工程量 |
| 3. 加运行时验证 | 沙箱跑测试（类 TREX），区分静态 vs 行为缺陷 | 中：需 CI/沙箱基建 |
| 4. 计费与分发 | credit 制 + MCP/CLI 接入主流 coding agent | 低–中 |
| 5. 高门槛项 | 达到 Greptile 级准确率、SOC 2、大客户自托管、与头部 agent 生态深度集成 | **高**：资金、合规、品牌、生态谈判 |

**可借鉴点（OPC 视角）**：对 Oscar「30 天拿第一笔收入」——垂直场景的「验证/审查 Agent」（如短剧投放素材合规审查、归因链路校验）比正面刚 Greptile 更现实；credit 制「按审查深度而非人头」的定价值得抄。

# 产品二：Halluminate — 垂直知识工作的 AI 训练环境与基准

## 1. 产品名称 & 一句话定位
**Halluminate**：为前沿 AI 模型构建「金融等知识工作的强化学习（RL）环境 + 基准」的数据研究实验室，自称「verticalized data research lab」。

## 2. 产品定位与目标用户
| 维度 | 内容 |
|---|---|
| 解决谁的问题 | 前沿模型在数学/代码等「可验证域」已很强，但在金融建模、客户级 PPT、战略分析等**需要判断与复杂交付的专业工作**上仍弱；模型厂缺高质量、带领域知识的训练/评测数据 |
| 目标用户 | **前沿闭源 AI 实验室**（官方称 top 5 美系闭源实验室中 4 家已是付费客户）；暂不以企业买家为主 |
| 首攻垂直 | 金融服务（投行/PE 尽职调查），正向咨询、保险、运营扩展 |

## 3. 核心价值主张
- **把专家判断变成训练信号**：从匿名真实 PE 交易抽 88 道尽调任务做基准（Westworld Due Diligence），7 个前沿模型最高平均分仅 **51%**——精准暴露推理失败点。
- **RL 环境即产品**：给模型厂提供可交互、高压力的经济模拟沙箱，Agent 可在其中执行交易、迭代逻辑，**无真实金融/合规风险**。
- **专家评测服务**：由前 Goldman/McKinsey/Capital One 等领域专家 + 粒子物理等跨界研究者做评估，弥补纯自动评测盲区。

## 4. 盈利与营收模式
- **B2B 卖「数据研究实验室」**：managed 沙箱环境（供 Agent 训练）+ 专有基准（给模型打分）+ 专家评测服务，按交付/项目向大模型厂收费。
- **经营数据（公司口径，经 Fortune 转述）**：10 个月内从 $0 增长到**中八位数（约数千万美元级）年化收入运行率**，且**强盈利**；9 人团队。→ 未独立审计，标不确定。
- 融资：$30M Series A（**Oak HC/FT 领投**，YC、Orange Collective、FT Partners、Heavybit 跟投，另有 Anthropic/OpenAI/Meta 个人研究者天使），累计 **$38.5M**；创始人 CEO Jerry Wu、CTO Wyatt Marshall（Cornell CS，2024 创立）。
- 资金用途：扩系统工程师 + AI 研究队伍、扩专用算力基建、加速金融模拟沙箱。

## 5. 关键成本结构与资源
- **领域数据获取与脱敏**：匿名真实 PE/金融交易数据是核心资产，获取与合规成本高。
- **专家网络**： Goldman/McKinsey/Capital One 等背景的评测人力。
- **专用算力**：用于跑 RL 环境与模拟（资金明确投向）。
- **小团队高产出**：9 人做到中八位数收入，说明边际成本极低、杠杆在「数据 × 专家」而非人头。

## 6. 获客与增长策略
- **直接打入大模型厂**：以「top 5 闭源实验室中 4 家付费」为信任锚，靠效果与独家数据获客。
- **基准即营销**：Westworld 公开基准成为行业参照系，反向引流训练环境订单。
- **YC + 顶级 fin 背景**：Oak HC/FT（金融科技 VC）、FT Partners 等带来行业人脉与背书。

## 7. 竞争壁垒
- **专有领域数据**：匿名真实交易/金融工作流，竞品难复制。
- **专家评测网络 + RL 环境构建 know-how**：把「专业判断」工程化的能力稀缺。
- **先发绑定头部实验室**：一旦进入训练管线，替换成本高。
- **软肋/风险**：客户高度集中（少数大模型厂），单一客户流失影响大；赛道拥挤化（同类 post-training 数据公司 Deeptune $43M A 被 Mercor 收购）——需持续扩垂直、建壁垒。

## 8. 可复刻该模式的关键步骤与门槛
| 步骤 | 内容 | 门槛 |
|---|---|---|
| 1. 选垂直 + 攒领域数据 | 锁定一个你/合作方有专有数据的行业（如海外短剧投放、广告归因），脱敏沉淀 | **低–中**：数据稀缺性是关键，有数据则低 |
| 2. 造基准 | 用真实任务做评测集，跑主流模型暴露失败点 | 低：开源评测框架可起步 |
| 3. 造 RL/模拟环境 | 把领域工作流做成可交互沙箱，供 Agent 试错 | 中：需工程化 |
| 4. 专家评测闭环 | 拉领域专家做质量把关，形成「数据—评测—环境」三位一体 | 中：专家资源 |
| 5. 高门槛项 | 打入大模型厂采购、做到中八位数收入、合规与规模化算力 | **高**：客户谈判与资金 |

**可借鉴点（OPC 视角）**：Oscar 手握海外短剧投放/归因的**专有数据资产**，最契合的复刻姿势不是做通用 Agent，而是把「短剧 ROI 归因、素材-回收链路」封装成**垂直评测/训练环境**，卖给做营销/投放 AI 的团队或大模型厂——这是 Halluminate 范式在小团队身上最现实的落地。

## 四、给 Oscar（OPC 视角）的可行动结论

1. **Greptile 教会的事**：AI 写代码变便宜后，「验证/审查」是比「生成」更稳的收费点；定价用「按用量/深度」而非「按人头」，更贴合 Agent 经济。
2. **Halluminate 教会的事**：你已有的垂直数据（短剧投放、归因）是做「领域评测/训练环境」型产品的天然素材，小团队也能走「卖铲子给 AI 产业链」的高毛利路线。
3. **今天两条的共同范式**：把自己行业的专有数据 + 专家判断，封装成「评测/验证」产品，卖给 AI 价值链的上下游——这比正面做通用 Agent 更易在 30 天内拿到第一笔收入。
