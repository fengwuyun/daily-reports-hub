## 一、AI 资讯

**1. OpenAI 承认 GPT-6.2 计费出错：修好后 Astra 触顶快 40%、Sol 快 25%，补一次可留存的额度重置（P0·成本账单）**

OpenAI Codex 与 ChatGPT 负责人 Thibault Sottiaux（Tibo）确认，GPT-6.2 上线初期存在计费错误，**大多数用户在使用 GPT-6.2 Astra 与 Sol 时被按折扣价扣额度**。修复后同样工作量消耗更多：**Astra 用户触及上限的速度比上周快 40%，Sol 快 25%**。他说与上一代 GPT-6 Astra、6.1 Sol 相比新模型额度仍更「耐用」。**不追溯补收差额**，补偿是给 Go、Plus、Pro、Business 各一次**可留存**的额度重置（11/26 起可用）；Business 用户 12/31 前免费用 Fast Mode。同期 Anthropic 也在给 Pro/Max/Ultra/Team 重置 11/10 以来的额度，领取入口 Settings > Usage，**有效期到 12/10**；Max 与 Ultra 另有每月 $100 / $200 的 API 额度。

判断：这条的真正含义不是「涨价」，是**标价一分没动，能用的量少了 25–40%**。它是本周三家公司（OpenAI 缩量、Google 降价、Anthropic 发补偿）同一动作谱系里最不体面的一档——**错误在你这边，成本转移在用户这边，且不给退**。对做预算的人来说，「每美元能买多少任务」这个分母这周被悄悄改了一次，而任何只盯刊例价的报价单都看不出来。

做法：① 如果你有 Codex / ChatGPT 订阅，**今天就去 Settings > Usage 领额度重置**，它是可留存的，不领等于白给；② 把团队「每月能跑多少条」的基线在 11/26 之后重测一次，别拿上周的数做 SLA；③ Business 档的免费 Fast Mode 12/31 到期，和年底其他到期项并到一张日历上。

⚠️ 40%/25% 来自 OpenAI 官方通知邮件与 Tibo 的公开表述（经 The Decoder、IT之家、凤凰科技 11/27 转述），**「快 40%」的基数是「上周的使用速度」，不是绝对配额**；官方未披露错误的具体计费字段。Anthropic 重置的有效期 12/10 来自其客户端提示，未见独立公告全文。

**3. AgentDuel 盲测：GPT-6.2 Sol 便宜 38%、掉了约 87 Elo，因为它的推理 token 中位数从约 1,200 掉到约 300（P0·判断）**

AgentDuel 是一个盲测编程 agent 对战系统：两个模型拿到同一提示、同一工具、同一 system prompt（跑在 OpenCode 2.3.2 的 fork 里），人不知道谁是谁来投票，票数用 Bradley–Terry 拟合到 Elo 尺度，**有 18 个模型达到 100+ 有效票**。数据：**Sol 6.1→6.2，单任务推理 token 中位数从约 1,200 掉到约 300（p = 0.00013），输出 token 从约 4,400 掉到约 3,300；同任务对手的推理量约 5,700 token**。**Astra 的推理 token 持平在约 1,400，Elo 从约 983 到约 988（没掉）**。成本侧：**Sol 相对对手从 0.81x 降到 0.50x（便宜 38%），Elo 从约 982 掉到约 895；Astra 从 5.7x 降到 3.6x（便宜 37%），Elo 没掉**。榜单 11/27 00:00 UTC 重算后，**Sol 排第 12、Elo 936（+54/−59）、$0.43/任务、1.7 分钟/任务**。

判断：**「同样的活，更便宜」和「更少的活，更便宜」是两件事**，官方话术把两者合成一句「token 更少、质量相同」，盲测数据只支持后者的一半——Astra 站住了，Sol 没站住。**这是「成本地板」这张表最该被读的方式：单价降 38% 而 Elo 掉 87 分，等于你花了更少的钱买到更少的思考。**对写代码、跑 agent 的人来说，便宜档的隐藏成本是**多轮返工**，而返工次数是你账单上最贵的那个乘数。

做法：① 你现在用 Sol 跑编码 agent 的，**把 11 月之前的成功率基线留一份**，因为榜单 Elo 改的是模型不是你；② 同一批任务同时跑 Astra 与 Sol，只比「一次过率」，不比单次成本——**一次过率差 10 个百分点，就足以吃掉 38% 的价差**；③ 置信区间是 ±55，**别拿一两天的名次波动当结论**，这条我要自己先说清。

⚠️ 本条为单一来源（dev.to 长文，作者自行从发布的 PNG 读图估算 token 中位数），**标注的 87 Elo 与实时榜单的 936 存在差异，作者自己也承认在噪声范围内**。AgentDuel 不是我刊实测，其提示集、工具集与真实业务分布未必一致；p 值只证明「token 确实变少了」，**不证明「质量下降」是唯一原因**。

源：dev.to 11/27（引 AgentDuel 榜单与 11/27 00:00 UTC 重算快照）

**4. OpenRouter：今年 token 用量涨 44 倍、支出只涨 7.6 倍、单价降 83%，但降价劲头近月明显转弱（P0·成本账单）**

OpenRouter 年度口径：**平台 token 用量涨 44 倍，用户支出只涨 7.6 倍，隐含单价降 83%**。同时它自己也说，**这股降价劲头近一个月已经明显弱了**。

判断：这是杰文斯悖论最干净的一次实测——**便宜 83%，所以用量涨 44 倍，最后总支出还是涨了 7.6 倍**。它推翻的是一个很常见的乐观假设：「单价降了，我的成本自然降」。真实情况是单价降了，你的用量涨得更快，**账单跟着涨**。而「降价劲头转弱」这句话更值得记：**当单价不再往下掉，用量却还在涨，成本的曲率就反过来了。**

做法：① 拿你自己上个月的 token 用量做分母，**算一次「单价 × 用量」而不是只看单价**；② 如果过去三个月你的用量涨得比单价跌得快，**下个月做预算时按用量线性外推，不要按单价打折外推**——这是这类预算最常见的错。

源：OpenRouter 年度数据（经今日码上八分钟 11/27、AI HOT 转述）

**5. Cognition 的 SWE-2 Flash：276B MoE / 每步 12B 激活，比旗舰快 3 倍、便宜到 1/5，11/30 前并入 Devin 免费档；同期传寻求 750 亿美元估值（P0·工具链）**

SWE-2 Flash 由 Inkling-Small 后训练而来，**276B 总参数、每次推理只激活 12B**，官方口径是**比旗舰 SWE-2 快 3 倍、价格为 1/5**，**11/30 前作为付费 Devin 用户的免费升级**。同期 Cognition 据报在**寻求 750 亿美元估值**——两个月前它刚完成 480 亿美元的 E 轮；公司还另发了一个声称基准分翻倍的编码模型。

判断：**「快 3 倍、便宜到 1/5」这个说法里藏着和 Sol 一样的坑**：12B 激活换来的速度提升，通常也意味着复杂任务上要更多轮。但它的商业含义更直接——**免费档到 11/30，这是一次有明确截止日的获客**。一家两个月前才 480 亿的公司现在要 750 亿，**Flash 的定价就是它的增长故事素材**，这决定了 12 月之后它大概率不会更便宜。

做法：① 如果你有 Devin 账号，**11/30 之前把手上最难的仓库丢给 Flash 跑一遍**，用免费窗口测它的失败模式，而不是测它的成功案例；② 别把 Flash 写进 12 月的生产链路，**它的价格是融资叙事的一部分，不是稳态价**。

⚠️ 「快 3 倍 / 1/5 价格」为公司口径，无第三方复测；750 亿估值为「据报」，**未见官方确认**；基准翻倍的模型与 Flash 是不同产品，关系未说明。

源：You On AI 实体页 11/27（汇总 Cognition 公开信息）

**6. 红果上线「时间锁」：单日 30 分钟到 12 小时共 14 档，到点锁屏要输四位密码；同期 AI 漫剧万次播放收益从 20 元掉到 1–2 元（P0·跟你业务直接相关）**

**11/24 红果短剧上线「时间锁」**：用户自设单日观看时长，**30 分钟到 12 小时共 14 档，到点自动锁定，输四位密码才能继续，忘记可申诉找回**。这不是孤立动作——10 月已上「休息提醒」「睡眠提醒」；**11/1 起新激活用户不再获得金币功能，12 月底前对全部用户下线金币**（剧集仍免费，取消的是「看剧赚钱」）。账本那一头在收窄：**真人短剧每千次曝光实际成交价从 2024 年的 30 元上下跌到 2026 年不足 20 元，AI 剧更低**；36 氪口径 2025 年红果收入超 150 亿元、分账 30 亿元。供给端更挤：**DataEye 统计 2026 上半年抖音端上新 AI 仿真人剧与漫剧 22.19 万部，播放破亿仅 1,055 部、占 0.48%**；从业者称 **AI 漫剧万次播放收益今年从 20 元降到 1–2 元，活跃承制方从一季度 1,216 家减到 698 家**。中信建投曾测算 2023 年微短剧 300 亿流水中 **80–90% 是买量成本、利润率约 5%**。合规侧的硬约束是 9/1 施行的《微短剧发展管理办法》——**平台不得使用诱导用户沉迷、过度消费的算法模型**；10/27 红果公告累计处置低质与同质化剧集 **20,426 部**。

判断：**平台主动给自己装刹车，只有一种解释——单用户价值已经跌到「多刷一分钟反而亏」**。万次播放 1–2 元这个数，意味着一条 100 万播放的漫剧收入 100–200 元；而承制方从 1,216 家掉到 698 家，是供给端先出清。**「时间锁」同时也是合规动作**：让用户自己画线，比平台替他画线怨气小，而且直接对应《办法》里那条「不得用算法诱导沉迷」。对做内容的人，这条的杀伤力不在流量，在**「走量」这个策略的数学基础没了**——当单价跌到 1–2 元/万次，靠 100 部赌 1 部就不再是概率游戏，是负期望。

做法：① **本周就把手上在跑的漫剧项目按「万次播放收益」重算一遍单集回本线**，用 1–2 元而不是 20 元；② 承制方名单从 1,216 缩到 698 这件事，反过来是机会——**能活下来的团队在挑本子，也就是说「好本子」现在是稀缺方**，你如果有剧本能力，议价位置比三个月前好；③ 12 月底金币全下线，**依赖「看剧赚钱」拉新的投放模型要提前换**，别等到 1 月才发现 ROI 崩了。

⚠️ 30 元→不足 20 元的 eCPM、20 元→1–2 元的万次播放收益、1,216→698 家承制方，**均为从业者与行业媒体转述，非平台披露**；《办法》条文与 10/27 的 20,426 部处置是官方/公告口径。红果 MAU 我刊已记录过 3.56 亿与 4.3 亿两个口径（QuestMobile 不同月份），本期不重复引用、不给结论。

源：网易·颗粒度财经 11/26、腾讯新闻（盘和林评论）11/26、DataEye / 36 氪 / 中信建投（经上述报道转述）

**7. FCC 附条件批准 SpaceX 部署至多 100 万颗「Starmind」算力卫星：2033 年 11 月前首颗入轨、2040 年 11 月前全部部署（P1·算力供给）**

当地时间 **11/25** FCC 发布许可文件，附条件批准 SpaceX 组建 **Starmind（星脑）** 轨道数据中心星座，**至多 100 万颗**，是美国历史上首张太空数据中心星座许可。卫星分布在 **500–1002 公里高度的六个非静止轨道壳层**，太阳能供电、星间激光链路互联，在轨处理数据后回传。硬时间表：**2033 年 11 月前首颗正式运营卫星入轨，2035 年 11 月前部署 10 万颗（10%），2038 年 11 月前完成半数，2040 年 11 月前全部完成**；送入 600 公里以上轨道前须先交最终版碎片处理方案。单颗 AI1 卫星**常规输出 120 千瓦、峰值 150 千瓦**，官方称「约等于地面一个现代化 AI 服务器机架」。反对方：**亚马逊、Viasat、美国天文学会**，FCC 收到**超 1,500 条公众意见**；亚马逊称该计划「不完整、不现实」。蓝色起源 3 月已申请至多 5.16 万颗（Project Sunrise），仍在等批。消息公布后 **SpaceX 股价 11/25 收涨 1.30%**。

判断：**「100 万颗」是许可上限，不是计划量**——卫星运营商常常多申请换设计弹性，这一点报道里也写了。真正可读的是时间表：**首颗最晚 2033 年，全部 2040 年**，也就是说这套东西在你可见的产品周期里不会影响任何一次 API 报价。它的现实意义在另一头：**地面数据中心正在被社区抵制、被电价和土地卡住，所以资本开始给「轨道」发许可证**。这和上周「亚洲数据中心 66 亿美元贷款推迟尽调」是同一件事的两面——地面那头的融资在退，天上这头的许可在进。

做法：无（P1 观察，十年尺度）。唯一可迁移的一条：**看这类消息先看时间表和「许可上限 vs 计划量」两个括号**，100 万这个数字本身不含任何近期信息量。

⚠️ 许可文件日期为 11/25，中文媒体集中披露在 11/26，落在本期窗口；「约等于一个机架」为公司口径；星舰成本能否降下来是该计划的前置条件，上周星舰第 15 次飞行完成二级回收、未完成超重型助推器回收。

## 二、热点 & 梗

**1. 十周便宜 80%，但没有一家实验室降过价**

起因：一份公开价格追踪显示，**AI 指数 55 分以上的顶级模型，混合价十周内从每百万 token 20 美元跌到 4 美元，降幅 80%**。经过：时间线很直——**9 月 5 日是 GPT-6 Astra 的 20 美元，9 月 23 日 Claude Opus 5.5 降到 8 美元，11 月 11 日 Gemini 4 Carbon 与随后发布的 GPT-6.2 Sol 双双来到 4 美元**。要命的地方在于：**这三步里没有任何一家把自己上一代旗舰的价目改过一行**，全是新一代以更低定价入场，把地板砸穿。当前：这条数据在中文圈被广泛转述成「AI 变便宜了」，但同一周 OpenAI 修计费错让 Astra 触顶快 40%、Sol 快 25%。

判断：**「降价」这个词在这里被用错了。**实验室做的不是降价，是**用新一代产品线重新定价，同时让老产品线原地不动守住毛利**——老客户不迁移就继续按老价付，迁移就接受新配额。**所以真正在往下走的不是「智能的价格」，是「新入场者的报价」。**这两件事在你做技术选型时的含义完全相反：前者意味着「等等更便宜」，后者意味着「你不换，就不会便宜」。而本周的配额新闻正好补上另一半——**报价低了，能用的量也在被调**。

做法：**把「等降价」这个策略从你的决策表里删掉**，换成「每次新模型发布时重测一次一次过率」。理由很直接：老旗舰不降价是行业惯例，你等的那个降永远不会来；而新模型的报价低、限制也新，只有重测才知道能不能用。

⚠️ 这份追踪的「混合价」算法未公开，与本期成本地板的算式（2M 入 + 500K 出）不是同一口径，**不能直接相加或换算**；「20→8→4」的三步均为各模型发布时的公开报价，非促销价。

源：公开价格追踪（经 11/27 中文 AI 日报转述）

**2. Sol 便宜 38%，代价是它少想了 4 倍**

起因：有人在 Hacker News 发帖（215 分）说「OpenAI 可能进入了成本控制模式」，论据是 GPT-6.2 的 Astra 与 Sol 单任务输出 token 和推理 token 都比 6 代、6.1 代降了。经过：AgentDuel 的盲测数据把这件事钉死了——**Sol 6.1→6.2，单任务推理 token 中位数从约 1,200 掉到约 300，p = 0.00013**；同一批任务上，它的对手推理量约 5,700 token。**Astra 的推理量持平在约 1,400**。成本上 **Sol 相对对手从 0.81x 降到 0.50x（便宜 38%）**，Elo 从约 982 掉到约 895；**Astra 从 5.7x 降到 3.6x（便宜 37%），Elo 从约 983 到约 988，一点没掉**。当前：实时榜单 11/27 重算后 Sol 排第 12、Elo 936（±55），作者自己也说这个差在噪声边界上。

判断：**同一个宣传语（「token 更少，质量相同」）套在两个模型上，只有一个成立。**Astra 是真的效率提升——同样的思考量，更便宜。Sol 是**少思考**——便宜 38%，推理量掉到四分之一。这两件事在账单上长得一模一样，在下游行为上完全相反。**这也是我见过的「成本地板」这张表最危险的地方：表上 Sol 和 Astra 都写着 $9，实际买到的东西差了四倍的思考。**对写代码的人，少想的成本不出现在单价里，出现在**你重试第 3 次的那一刻**。

做法：**别拿单价选模型，拿「一次过率」选。**具体动作：同一批 20 个真实任务，Astra 跑一遍、Sol 跑一遍，记录「第几次通过」。**如果 Sol 平均要多 1.4 次，38% 的价差就被吃干净了。**这个测试两小时能做完，比读任何榜单都准。

⚠️ 单一来源（dev.to 长文，作者自行从图表 PNG 读值），**token 中位数为估算**；「掉了 87 Elo」与实时榜单的 936 不一致，作者已注明在 ±55 置信区间内，**即「下降」方向可信、「87 分」这个具体数字不可信**。p 值只证明 token 变少，不证明质量下降是唯一原因。

源：dev.to 11/27、Hacker News 讨论（215 分）

**3. 两个 AI 在电话里为一个 12 美元的账单吵，人早就走了**

起因：极客公园的一篇专栏设想了一个场景——你的 AI 代你打客服电话，去争一笔 12 美元的错账。经过：电话接通，对面也是 AI。**两个机器人开始就这 12 美元往复谈判，一个引条款，一个套话术，谁也不累、谁也不会挂电话。**而真正的那个人——不管是打出去的那个还是接进来的那个——**早就走开了**。当前：这不是新闻，是评论；但它描述的状态在本周已经部分成真：Claude 能以参会者身份加入会议、豆包的虚拟桌面能在 Windows 里替你看屏幕点按钮、企业客服侧的 AI 接线早已是标配。

判断：**AI 对 AI 的谈判，成本结构是反的。**人类谈判贵在时间，所以双方都有动力尽快收敛；机器谈判的时间成本近似为零，于是**唯一能终止它的只剩「某一方的预算」或「某一方的规则」**。这就把客服这个行当的核心指标从「解决率」变成了「谁先耗尽 token」。更现实的一层：**当两侧都是机器，商家没有理由再为「人的耐心」设计流程**——你等 40 分钟没人接是痛点，两个 bot 谈 40 分钟没人管就只是个账单。

做法：如果你在做客服/投放侧的自动化，**给 agent 设一个「人类回来就交权」的硬阈值**（轮次或时长），而不是设「谈成了就通知」——本周三条工具新闻都说明，agent 能自己跑很久，缺的从来不是能力是收手的条件。

⚠️ 该场景为评论性设想，非已发生事件；Claude Meetings「不录音」、豆包「虚拟桌面内运行」为公司口径。

源：极客公园专栏（经极客公园 11/27 隔夜汇总转述）

**4. Karpathy 用 7 小时、4.5 万行代码，把 31 个美国真实数据源做成了一张「文明」地图**

起因：Andrej Karpathy 想验证一件事——现在的编码 agent 能不能扛住「大规模但可验证」的活。经过：他用 **Claude Code 桌面版 + Opus 5.5（开 ultracode 模式）跑了 7 小时，生成约 4.5 万行代码**，把**美国人口普查局、经济分析局、劳工统计局、能源署、海洋大气局等 31 个真实数据源**整合到一张**25 公里六边形网格**上，做成《文明》风格的游戏地图——**GDP 映射成金产量，城市按人口点亮**。当前：这条在 builder 圈被当成 vibe coding 的最好演示。

判断：值得记的不是 4.5 万行，是**为什么这件事能成**。它满足三个条件：**数据源是公开的、口径是确定的、结果是可视化的**。也就是说**「对不对」这件事机器自己能查**——人口数对不上普查局就是错，GDP 映射错了图就歪。对比一下写业务代码：需求是模糊的、验收是人给的、对错要等三个月后的报表。**这才是「AI 能写多少代码」这件事的真实分界线：不是代码量，是可验证性。**同一天 Amjad Masad 的说法是「大规模软件迁移现在可行，前提是你验得了结果」——两个人说的是同一件事。

做法：**把你要交给 agent 的活按「能不能自动验收」排个序**，先做能自动验收的那一半（数据清洗、格式转换、批量生成分镜描述、口径核对），把不能验收的（选题、判断、谈判）留在人这边。这个排序比选哪个模型更能决定你的产出。

⚠️ Karpathy 本人的公开帖，**代码行数与耗时为其自述，未见第三方复现**；「31 个数据源」的清单以其帖子为准；地图为个人项目，非产品。

源：Karpathy 公开帖（经今日码上八分钟 11/27、AI观察员 11/27 转述）

## 三、潜在挣小钱的机会

**1. 把「faceless 视频」做成订阅制工作室：$54,400 MRR，已验证收款**

路径：**按月订阅的「无露脸视频」生产线**——脚本、AI 配音、剪辑、缩略图全包，客户按固定条数/月付费。这不是工具，是**产品化服务**（productized service）：客户买的不是软件，是「这周有 5 条能发的视频」。

报价与月收入：**MRR $54,400，Stripe 已验（2026-11-04 同步）**。客单价与客户数**未披露**。

为什么复刻得动：它的护城河不在技术，在**交付节奏和排版规范**——AI 配音和剪辑工具人人都有，能把「10 条/月、每周二交、缩略图统一风格」稳定交付的团队很少。**这是运营活，不是研发活**，所以一个人的产能上限就是它的天花板，也正因为如此它不需要融资。

⚠️ 风险：① **收入 ≈ 人力 × 产能，MRR 不等于利润**，$54,400 里有多少是外包成本未披露；② **纯 AI 内容的平台政策在收紧**——11/25 期已记 Tidal 12/9 起删 2700 万首纯 AI 音乐，YouTube/TikTok 的 AI 标注与限流规则同理；③ 客户集中在少数几个频道时，一个账号政策变动就能打掉整条线。

源：theaireceipts.com（TrustMRR / Stripe 验证，2026-11-04）

**2. 把多家图像/视频/音乐模型包成一张账单：$29,900 MRR、740 订阅、累计 $553,000**

路径：**一个 API / 一个 key / 一张账单，背后接 400 多个图像、视频、音乐模型**，按 credits 卖，**从 $39/月起**。官方列出与 BytePlus、阿里云、MiniMax 的合作关系。这是「聚合层」生意——客户不想为每个模型单独开户、单独充值、单独对账。

报价与月收入：**MRR $29,900、740 个活跃订阅（折合约 $41/订阅/月）、近 30 天 $39,700、累计 $553,000，Stripe 已验（2026-11-04）**。它 2021 年 8 月就成立，2026 年 4 月才 $17,200，9 月 $47,000——**是慢热型，不是爆发型**。

为什么值得看：**这是本周「同一模型两个价目」那条的正面版本**。同样一件事（把多家模型的价差变成自己的毛利），有上游授权的做成了 $29,900 MRR 的生意，没授权的就是 11/24 期 Dragos 测出来的「偷 key 的聚合渠道」。**区别不在技术，在一纸协议。**

⚠️ 风险：① **毛利被上游随时调价吃掉**——今天顶级模型混合价十周降 80%，你昨天谈的进货价今天就是亏损价；② **合规与信任成本极高**，客户会问你 key 存哪、日志留多久；③ 这是**十年级别的慢生意**，别按 SaaS 的增速预期它。

源：theaireceipts.com + TrustMRR 11/04 快照

**3. $9/月的 AI 字幕：从上线到 $3,100 MRR 用了约 7 个月**

路径：**纯字幕工具，$9/月**，带免费层。功能是转写 + 烧字幕，commodity 到不能再 commodity。

报价与月收入：**MRR $3,100（已验）**，$9/月档，**上线到约 $3.4k MRR 约 7 个月**。

为什么这条要用「反向」的方式读：它是本期最有用的一个**价格校准器**。你要做短剧出海的字幕/译制工具，第一个问题不是「功能怎么做得更好」，是「这个市场愿意付多少钱」。答案在这里：**$9/月，而且做了 7 个月才 $3,100。**这不是一个失败的案例，这是一个**诚实的市场出清价**。同期 $54,400 的 faceless 工作室卖的是「交付」，$29,900 的聚合 API 卖的是「省事」，只有纯工具卖的是「功能」——**功能是这三种里最不值钱的**。

**ArcReel/ArcReel（主推·把剧本拆成角色、场景、道具、分镜、视频，最后导成剪映草稿）**
- 是什么：AI Agent 驱动的**可自部署视频工作台**。输入小说或剧本，输出**角色 / 场景 / 道具资产 → 分镜 → 视频 → 可播放成片或剪映草稿**。**6.8k stars、1.4k forks、27 watching、Python、AGPL-3.0、11/26 仍在提交**，官网 arc-reel.com，基于 Claude Agent SDK，Docker + FFmpeg 部署
- 差异化：同类工具做的是「一句话出片」，它做的是**「资产先立住，再出片」**——**跨镜头复用角色、场景、道具的参考图素材，保留生成历史以便对比和回滚**；按项目分别配置文本、图像、视频、配音能力（问题区里能看到 Vidu Q3 Mix、Vertex Veo 3.1 Fast、Seedance 2.5 4K、Kling Image 4.0、百炼 decision-model 的在办条目），**生成前给费用预估、调用后给实际用量**。两条最硬的功能：**跨镜头一致性**与**剪映草稿导出**
- 用在哪：**漫剧/短剧的分镜到成片这一段**，尤其「同一角色出现在 40 个镜头里还得是同一个人」这个卡点。具体用法：把你已有的角色设定图导进去当参考素材，让它先生成 3 集分镜，**验收只看一件事——第 30 个镜头里的脸还认得出是第 1 个镜头里的人吗**；过了再批量跑，最后导草稿进剪映做人工精修。**它不替代剪映，它替代的是「在剪映里一帧一帧对齐角色」这件事**
- ⚠️ 风险：**issue 编号已到 #4193**（含已关闭），问题量极大，属高速迭代期产品，**接口和数据结构会变**；README 明确警告**默认 Compose 会把 1241 端口发布到宿主机所有网络接口，远程访问必须先配认证 + HTTPS 反代**，直接暴露等于把「能花你 API 额度的后台」挂公网；**CapCut 兼容性官方说未验证**，导出只对**中国大陆版剪映**有承诺；AGPL-3.0 意味着你改了再对外提供服务要开源

**headroomlabs-ai/headroom（主推·在内容进模型之前把它压一遍，答案不变，输入的 token 少一半）**

- 是什么：**上下文压缩层**。在内容进 LLM **之前**压缩 agent 读到的一切：**工具输出、日志、RAG 分块、文件、对话历史**。**80.9k stars、6.4k forks、Apache-2.0、3,835 次提交、199 个 PR、11/26 最后提交（6a50f22）**，主仓 Python + Rust 核心 + TypeScript SDK
- 差异化：**它压的不是 prompt，是 prompt 里的垃圾**。ContentRouter 先判类型再分派：SmartCrusher 专压 JSON（保留错误项、统计异常值、首尾边界）、CodeCompressor 做 AST 感知的代码压缩（覆盖 8 种语言）、Kompress-v2-base 压散文、CacheAligner 只**标记**会破坏 KV 缓存前缀的易变内容但**从不重写 prompt**，另有**可逆压缩（CCR）**——原始内容本地存着，模型需要时调 `headroom_retrieve` 取回。实测压缩耗时 **p50 0.21 ms（10K token JSON）、1.4 ms（100K）**，不拖 agent 延迟
- 用在哪：**你自己的 agent 账单**。它给的四组实测最能说明该用在哪：**代码搜索 100 条结果 21%、SRE 事件排查 57%、代码库探索 42%、GitHub issue 分类 30%**；重复 JSON 数组与日志行压缩率**超 90%**；输出侧有个默认关闭的 verbosity steering，实测报告能砍 **31.7%**。对短剧业务最直接的一处：**投放日报、平台规则 PDF 抽出的字段表、历史对账表**——这些是典型的高重复 JSON/表格，正是它压缩率最高的一类
- ⚠️ 风险：**它对散文和已经很密集的输出收益极小**，低于 `min_input_words` 的块逐字节原样返回，**别指望它压你的剧本**；README 自己说，如果你已经在用提供商原生压缩（如 OpenAI Compaction）且不需要可逆性，**可能根本不需要它**；**遥测默认开启**（匿名 beacon，不含 prompt/内容/路径），企业环境要用 `HEADROOM_TELEMETRY=off` 或 `HEADROOM_OFFLINE=1`；平台支持不均——**原生 wheel 覆盖 macOS Apple Silicon 与 Linux，Intel macOS 要手动指 ONNX Runtime，x86 需要 AVX2**；**80.9k stars 说明它是成熟项目而非早期玩具**，反过来说它的抽象层已经厚了，接入前先读 Limitations 那页
- 源：GitHub headroomlabs-ai/headroom 仓库与 README / Limitations（11/27 抓取）

**tday.com（备选·让编码 agent 自己把你的产品录成一条带旁白的 demo 视频）**
- 是什么：**商业产品（SaaS，非开源）**。你在 Claude Code / Cursor / Codex 里给一句指令，**你的 agent 在本机把产品跑一遍并录下来**，tday.com 负责写旁白、配音、加光标与镜头、字幕、片头片尾、品牌色和音乐，最后给一条可编辑可分享的 demo。支持 Web、桌面、终端、iPhone、Android
- 差异化：**它不是录屏工具，是「让 agent 自己录」**。走 MCP：`demo_start`（起一个**一次性副本**，独立端口、独立种子数据库，不动你的 dev server）、`demo_beat`（逐个镜头执行）、`demo_review`（本机自检，**查屏幕上有没有出现密钥或本地环境变量**）、`demo_upload`。品牌是从你的官网读 logo、配色、字体，不是手填；**产品改了会重新录并标记旧 demo 过期**
- 用在哪：**短剧/漫剧工具的内部演示与对外招商素材**——你给投流代理、给承制方讲「这套工作流怎么跑」，最费时的从来不是讲，是录。另一个更实用的用法：**每周给老板/合作方发一条「这周新功能怎么用」的 40 秒视频**，比写周报省时间
- ⚠️ 风险：**它是托管服务，不是自持**——视频、截图、旁白与步骤记录会上传，源码/.env/cookie/网络流量不上传（官方口径），但**上传这件事本身要你接受**；**定价按「保存的 demo 数」收**：Free 5 条、Pro $39/月 25 条、Growth $149/月 150 条、Enterprise 另议，**产品迭代快时「条数」会比你想的更早用光**；它只解决「demo 视频」，**不解决「这条 demo 讲得好不好」**——脚本还是它写的，你的产品如果本身讲不清，它只会把「讲不清」录得更清楚
- 源：tday.com 官网与定价页 / FAQ（11/27 抓取）
