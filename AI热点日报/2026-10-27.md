## 四、小而美产品

**1. Llama Windows（主推）——一个本地 AI 服务器喂饱所有 Windows 应用**
它是什么：把 llama.cpp 塞进 Windows 11 系统托盘，一键从 Hugging Face 下模型，提供共享的本地 OpenAI 兼容 API + 模型缓存，编码 agent、编辑器、脚本共用同一批本地模型，Alt+Space 呼出聊天（PH 10/25 日榜第 6，125 票）。
差异化：不是又一个聊天客户端，而是"本地模型基础设施"——装一次，全系统应用都能指到 localhost 的 OpenAI 兼容端点；数据不出机。
用在哪：把 DeepSeek/GLM 小模型挂本机给脚本和 agent 跑批兜底，官方 API 抖动时本地顶上；敏感数据（投放账户表、用户明细）从此不过外网。

**2. AVP（主推）——给 coding agent 用的开源版 Git 替代协议**
它是什么：Murmell（2 人团队）开源的 Agent Versioning Protocol：agent 开任务、写入、直接 landing，每次 landing 都在 main 最新头秒级验证；产物仍是普通 Git commit，GitHub 和部署流程不用改（PH 10/26，76 票）。背景：Anthropic 的 agent 把 monorepo 日合并量从 2500 干到 3 万后弃用 Git，但 Scion 不开源——AVP 是这个思路的开源版。
差异化：CI 从每天 104 次 PR 构建降到 4 次；6–8 个 agent 同仓库时 Git/Jujutsu 会 main 变红、任务丢失，AVP 全程绿且不丢任务（官方基准，⚠️自测口径）。
用在哪：多 agent 并行改同一批脚本/仓库时的版本层，开源可自部署，配你现有的 Claude Code/Codex 工作流。

**3. Openstatus Incident Management（备选）——小团队开源事故管理**
它是什么：开源的事故管理软件，配合监控和状态页使用：Slack 里一键宣告事故、自动建事故频道、维护时间线、起草复盘（PH 10/25 日榜第 4，168 票）。
差异化：不做监控本身，只做"出事之后的流程层"；开源可自部署。
用在哪：你的自动化链路（日报推送、跑批采集）真挂了的时候，有比"翻聊天记录"体面的排障与复盘记录。⚠️ 更适合协作场景，单人用偏重。
