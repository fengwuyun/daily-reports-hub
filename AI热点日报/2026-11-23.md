## 一、AI 资讯

**1. 服务器厂商在交付前加价 25–45%：HPE 已把「重新定价权」写进报价条款（P0·成本账单·跟你业务直接相关）**

《金融时报》11/22 报道，戴尔、慧与（HPE）、联想、超微电脑对已签约、尚未交付的 AI 服务器订单，要求客户在合同价基础上追加 **25%–45%**。受影响的买家包括简街资本（Jane Street）、Optiver、哈德逊河交易公司（Hudson River Trading）等自建数据中心的量化机构。三名关键事实：① 一名客户的原话是「遇到 25%、30% 甚至 45% 的涨价，实在令人不安」；② 摩根大通测算内存成本自 2024 年初以来累计上涨 **超 400%**，内存已占服务器物料成本一半以上，涨价主要是转嫁内存；③ HPE 已经在报价条款里写入了「交付前重新定价权」。

纠纷已有判例在路上：今年 6 月 XTX Markets 在爱尔兰起诉戴尔，法庭文件显示双方原定服务器固定总价 **5.49 亿美元**，XTX 另付 500 万美元「锁定价格」，戴尔随后要求至少再付 **6,200 万–7,000 万美元**才能提货。

判断：算力采购的计价基准正在从「签约日」漂移到「交付日」。这件事对个人开发者的直接含义不是「服务器贵了」，而是**云厂商的资本开支账单会被同样传导下来**——HPE 能对量化基金加价 45%，云厂商对按量客户只会做得更平滑：不上调单价，改调折扣、改调阶梯。过去两年「等下一代卡降价」的经验，在这一轮里暂时失效。

做法：本周内把手上的算力/API 合同翻出来，只看两件事——有没有「价格锁定」条款、有没有「交付/生效前调价上限」。没有的，补一条邮件留痕问对方：下一财年的报价有效期到哪天。如果是按月付的云账单，把最近三个月的单价曲线拉出来，折扣率往下走就是传导信号，比单价上涨早一个季度能看到。

⚠️ 25%–45% 是「部分客户」的个案区间，不是全行业普涨；戴尔、联想未回复采访，HPE、超微拒绝置评；GPU 服务器涨幅 20–30%、CPU 节点涨到 3 倍以上均为消息人士口径；合同是否写明交付期调价条款，接触到的采购方均未确认。

源：Financial Times 11/22（经 IT之家、环球市场播报 11/23 转述）、新浪财经 11/23、摩根大通测算

**2. 华为云贵阳一 region：DeepSeek-V4.1-Flash-1017 的「缓存命中输入」降到原价 20%（P0·成本账单·跟你业务直接相关）**

华为云 11/23 公告，MaaS 模型即服务自 **2026-11-23 00:00（北京时间）** 起下调**贵阳一 region** 的 DeepSeek-V4.1-Flash-1017 价格：**「缓存命中输入」调整为原价的 20%，其他价格不变**。11/21 期记录过华为云香港区的同类 2 折动作，本期公告为贵阳一；两地是否同批发布，公告未说明，按 region 分别看。

判断：缓存命中打 2 折，对「提示词固定、只有尾部变化」的场景是结构性降价——系统提示 + 剧本模板 + 平台规则那一大段全走缓存，重复部分成本降 80%。它奖励的是**提示词工程里的「稳定前缀」**，惩罚的是「每次重新拼一段新 prompt」。同一天 DeepSeek 官方刊例没动，所以这不是模型降价，是**托管方的缓存策略在降价**——同型号在不同云上的实际单价已经分叉。

做法：如果你的批处理链路（分镜描述、剧本打标、投放文案批量改写）每次请求都带一大段固定前缀，今天就能测：把固定部分放最前面、变量放最后，连续两次请求看返回里的缓存命中字段。命中率从 0 到 80% 就是这条公告给你的全部收益，不用换模型、不用改业务。反过来，如果提示词每次结构都在变（比如把日期、随机 ID 放在开头），先修这个，再谈省钱。

⚠️ 公告只写「原价的 20%」，未给该 region 的绝对单价，做预算请以华为云价目页当日数字为准，不要用其他 region 折算；缓存命中依赖前缀完全一致，改一个字符就整段失效；贵阳一的模型版本是 1017，与你实际调用的版本号要对上。

源：华为云降价公告 11/23（经界面新闻、腾讯新闻 11/23 转述）

**3. 英伟达一天涨超 8%、存储链集体反弹：11/21 那场抛售被买回来了（P1·钱）**

11/23 美股盘前与盘中，AI 硬件链普涨：**英伟达 +8.19%、台积电 +8%、SK 海力士 +9.15%、美光 +7.48%、希捷 +8.31%、AMD +6.23%**，服务器侧**戴尔 +9.02%、超微 +8.08%、HPE +7.09%**，三倍做多半导体 ETF（SOXL）+17.40%。同期 Anthropic（ANT）+3.26%、SpaceX +3.30%。触发因素有三：特朗普 11/22 再次公开呼吁英伟达董事会重新聘用黄仁勋（财长贝森特回应「黄仁勋现在已经是外部人士了」）；摩根士丹利威尔逊称上周的恐慌性抛售是「难得的买入机会」；高盛给出美股筑底三条件（AI 盈利信心回升、美联储转鸽、仓位大幅回落），满足其一即可。

判断：把 11/21 的 −14% 和今天的 +8% 放在一起看，这更像一次**仓位事件**而不是需求事件——上一期的下跌由「AI 交易整体去杠杆」驱动，今天的反弹由「同一批资金回补」驱动，中间没有任何一条关于订单或毛利率的新事实。真正的信号在第 1 条：交付前加价 45% 说明供给仍然紧。价格在跌、实物在涨，这种背离通常不会维持太久。

做法：别用单日涨跌改判断。要看的是「加价能不能落地」——如果 12 月财报季里戴尔、HPE 承认把 25–45% 的涨价转嫁成功，那 AI 硬件的毛利结构就变了；如果被客户顶回去，涨价就是纸面。对个人没有仓位动作建议，只有一条：把「上周跌 14%」从你的行业判断里删掉，它不构成证据。

⚠️ 上述涨跌幅为 11/23 北京时间 17:00 后盘前/盘中数据，收盘可能不同；「恐慌抛售是买点」为卖方观点，非事实；贝森特表述为其个人回应，不代表政府立场。

源：每日经济新闻 11/23、腾讯新闻 11/23（盘前行情）、CNBC / 路透 11/22–23

**4. 内存走出两个方向：DRAM 合约价 2027 年预计涨 40%，NAND 却在 2027Q1 转跌（P1·判断）**

三条同向的数据摆在一起：① 韩国 KB 证券 11/20 报告预计，2027 年全球 DRAM 需求同比 +25%、供给仅 +18%，服务器 DRAM 需求 +56%，主要客户供货满足率仅约 **70%**；按合约价算，三星与 SK 海力士 2027 年 DRAM 均价同比 **+40%**、NAND **+30%**。② TrendForce 同期把 2026Q4 NAND 合约价涨幅预测从 15–20% **下调到 8–13%**，并预计 **2027Q1 转为下跌 0–5%**、Q2 起全品类下行。③ 中国云厂商削减 2027 年企业级 SSD 订单的规模**已超过北美新增需求**，2027 年全球 NAND 位供给仍将增长 25–30%。

判断：AI 吃的是 HBM 与服务器 DRAM，不是 NAND。所以「内存涨价」这句话在 2027 年会分成两半——训练/推理要的那半边继续紧，存素材、存归档、存日志的那半边转向过剩。对做内容的人这不是宏观新闻：你的短剧素材库、成片归档、投放素材备份，吃的是 NAND 那一半。**明年存储侧的成本方向是往下，不是往上。**

做法：分两笔账。① 素材/归档：2027 上半年再签对象存储或冷归档的多年合约，现在签会锁在高位；② 推理/训练：能用 API 就别自建，自建要接受 DRAM 涨价传导（第 1 条已经发生）。如果正在算「自建推理比 API 便宜多少」的账，把内存涨幅按 40% 重算一遍，结论经常反过来。

⚠️ 40%/30% 是 KB 证券对合约价的**预测**，不是已发生；TrendForce 的 NAND 转跌同样是预测，且现货与合约价差已扩大到 20% 以上，两个口径不能混用；「中国云厂商减单超北美新增」为 TrendForce 口径，无官方确认。

源：KB 证券报告 11/20（经韩联社、Seoul Economic Daily、DIGITIMES 转述）、TrendForce 2026Q4 预测、算力风向标每日简报 11/23

**5. 内存在涨价，英伟达却在下一代旗舰上减配：Rubin Ultra 每颗 GPU 只装 192GB HBM，比 B300 少三分之一（P1·判断）**

SemiAnalysis 披露，英伟达明年旗舰 **Rubin Ultra 每颗 GPU 只配 192GB HBM**，比当前的 B300 与今年标准版 Rubin **少三分之一**。同期对照的价格侧：HBM 单颗售价已接近 **560 美元**（按重量算贵过黄金），三星给 HBM4 的明年报价约 **每 GB 32–40 美元**，是上一代的 3 倍；SK 海力士当前日赚约 4 亿多美元；美光 CEO 在财报电话会上称「看不到供需平衡点」。

判断：这是「容量」与「带宽」被分开定价的结果。HBM 的瓶颈不在堆多少层，在底部进出数据的通道数——买家真正稀缺的是带宽，不是容量。英伟达在单卡上砍容量、靠更大机柜补总量，说明它在为「单位带宽成本」做优化，而不是为「单卡能装多大模型」做优化。对推理侧的含义是：**未来一年「一张卡跑完整个模型」的路线会更难，多卡拆分与 MoE 稀疏化会更划算。**

做法：如果你在规划本地部署（哪怕只是评估），把判断标准从「显存多大」换成「每 token 的实际成本」。同一张卡，显存够但带宽不够时，长上下文场景的吞吐会掉到不可用；反过来，MoE 类模型（激活参数远小于总参数）在小显存上反而更实际。评估表里加一列「激活参数 / 总参数」，比加一列显存有用。

⚠️ 192GB 为 SemiAnalysis 单一信源披露，英伟达未确认；560 美元/颗、32–40 美元/GB 为媒体与厂商报价口径，不同 HBM 代际不可直接比；「贵过黄金」是比喻，不是定价依据。

源：SemiAnalysis（经星海情报局 11/23 转述）、三星 HBM4 报价（媒体口径）、美光财报电话会

**6. 亚马逊接近以 75 亿美元收购 Decart：买的不是模型，是「让别人的芯片跑得更快」（P0·钱）**

《金融时报》11/22 报道，Amazon 已就收购 Decart 进入深入谈判，作价约 **75 亿美元**，最早可能本周初达成，仍有破裂风险。Decart 2023 年由三位以色列工程师创立，做跨硬件类型的 AI 栈优化，同时自研世界模型；它是 AWS **Trainium3** ASIC 的早期使用者之一，在优化亚马逊自研芯片上有实际经验。今年 5 月它以 **40 亿美元估值**完成 **3 亿美元 B 轮**，投资方包括亚马逊自己、英伟达、Adobe、丰田、eBay；Anthropic 曾表达过收购兴趣。

判断：75 亿买一家 5 月还值 40 亿的公司，半年溢价 87%，买的逻辑不是模型能力，是**「把自家 ASIC 的实际吞吐榨出来」这项能力**。同一周里英伟达在减 HBM 配置、服务器厂在加价 45%，三条线指向同一件事：算力的瓶颈正从「买不到卡」转向「买到了也用不满」。谁能让现有硬件多跑 30%，谁就值钱。

做法：这条对个人开发者唯一的可用推论是——**别把优化预算全押在换模型上**。同一份任务，换模型通常能带来 20–40% 的成本变化，但提示词结构、批处理粒度、缓存命中、并发控制这四项加起来经常超过 50%，且不依赖任何供应商。本周拿一个真实任务做对照：原样跑一遍，只改缓存与批处理再跑一遍，记下两次的实际账单。

⚠️ 交易尚未官宣，FT 称仍可能破裂；「最早本周初达成」为谈判进度口径；Anthropic 的兴趣为报道所述，无官方确认。

源：Financial Times 11/22（经 IT之家 11/23 转述）

**7. 微信把短剧塞进发现页：绿泡泡 11/22 上独立小程序、看一看内测短剧入口，9 月月活已到 1.56 亿（P0·跟你业务直接相关）**

三条新增事实（机制层面 11/22 期已写过，本期只记入口与体量）：① **11/22 腾讯上线「绿泡泡短剧」独立小程序**，把观看、传播、投流串成闭环；② 微信「**看一看**」在小范围测试短剧入口，与「看一看」原有内容并列；③ QuestMobile 11 月报告口径：截至 9 月，绿泡泡短剧以 **1.56 亿月活**成为微信小程序短剧第一，同期红果 **4.3 亿**。增长曲线：7 月更名「绿泡泡」，10 月首周周活逼近 9000 万。流传的一份专家纪要称其日活已达 1800–1900 万、日流水约 1600 万元、内部目标 2027 年 8 月日活 5000 万——**该纪要口径未经官方确认，本刊不采信，仅记录其存在**。

判断：绿泡泡真正改变的不是分账比例，是**入口层级**。从「搜小程序」到「发现页一级入口」，意味着短剧从「用户主动找」变成「用户被推送」——这会重演视频号 2020 年的路径：入口一开，供给端立刻过剩，然后靠人均时长筛内容。它同时解释了另一件事：为什么 12/1 的单集时长新规（≥1 分钟）会在这个时点落地——发现页要的是「可连续观看的时长」，不是「30 秒钩子」。

做法：把手上剧集按「单集 60–90 秒」重新剪一版，专门跑微信侧。绿泡泡的考核是人均播放时长（≥10 分钟拿激励），这意味着**前 3 集的连播顺滑度比单集钩子更重要**——把第 1 集结尾的钩子做成「直接进第 2 集」而不是「引导关注」。同时算一笔：IAA 模式下你的收入 = 播放量 × 广告填充率，投流成本必须自己扛（纪要口径：片方日投流 1200–1300 万才撑起 1600 万日流水），先小批量测 ROI，别一次押全集。

⚠️ 1.56 亿与 4.3 亿均为 QuestMobile 单一口径，与 11/20 期引用的「红果 MAU 3.56 亿」不一致，两个口径并列、不给唯一结论；「看一看内测」为小范围灰度，未见官方公告；专家纪要不采信；IAA 收入依赖广告填充率，不同剧类差异极大。

源：什么值得买社区整理（引 QuestMobile 11 月报告、36氪、界面新闻）11/23、网易 11/23、财经网科技

**8. TikTok 给 AI 重制短剧立规矩：只能关联同机构已发布原版、禁止二级套娃、上线前签内容许可协议（P0·跟你业务直接相关·出海）**

按行业自媒体转述的规则要点：① AI 重制短剧**仅可关联同机构旗下已正式发布的原版剧集**，重制后的剧集**不能作为母版**再次关联，只保留「原剧 → AI 重制剧」**单级**关系，禁止无限层级套娃；② 所有 AI 重制短剧上线前必须完成《**内容许可协议**》签署；③ 配套数据：2026 年 1–7 月 TikTok 短剧全球累计分成突破 **1.1 亿美元**（约 8.06 亿人民币），**7 月单月 2,900 万美元**，**本土 AI 短剧分账环比 +34%**；此前已上线独立短剧入口 Short Dramas。行业侧动作：昆仑万维称团队计划每月上线 800–1000 部 AI 短剧；海外平台 CandyJar 推出男频 AI 短剧平台 Ironblood。

判断：这套规则的实质是把「重制」变成**需要授权链的一条流水线工序**，而不是「拿到片子就能改」。单级关联这一条最关键——它直接掐死了「A 家的剧 → B 重制 → C 再重制」的二道贩子路径，也让「谁有权重制」这件事第一次有了平台侧的归属字段。对做出海的正规团队，这是净利好：你的原创库变成了可反复变现的资产，而不是被搬运的素材。

做法：本周做一份「重制授权台账」——每部可重制剧登记四列：原剧 ID、版权方、授权范围（地区/语言/期限）、AI 重制版本号。上线前把这份表连同《内容许可协议》一起归档，平台一旦追溯，你能在十分钟内交出来。反过来，如果手上有一批来源不清的「素材剧」，别重制，这是这套规则下最容易被一次性清空的资产。

**9. AI 短剧的「盗脸」被官方媒体定性：普通人也在被用，最高法 9 月已给过口径（P0·跟你业务直接相关·合规）**

## 二、热点 & 梗

**1. 黎曼猜想「机器认了、人类没认」：社区确认代码无误，克雷官网还写着未解决**

起因：11/21 前后，Anthropic 研究员 Levent Alpöge 公布一套约 **1,700 万行**的 Lean 证明库，声称与 Claude 合作完成了黎曼猜想的形式化证明。经过：11/22–23，**Lean 与 Mathlib 社区发布联合声明，正式确认该证明库编译通过、命题与证明核对无误**，独立检查器完成验证——这一步是纯机械的，不带数学判断。当前状态：三方立场分化。丘成桐称「数学进入新纪元」；陶哲轩明确保留，认为要真正消化还需很久；袁新意在知乎提出「或许我们高估了黎曼猜想的难度」，成为知乎热榜第一（热度 1,225 万）。而**克雷数学研究所官网仍将黎曼猜想列为未解决**——百万美元奖金的前提是「数学界接受」，不是「编译器接受」。

附加细节：这套证明有另一个流传的数字「25 万页」。它是把代码行折算成纸面的估算，与 1,700 万行不是同一件事，两个数字常被混着说。

判断：「编译通过」和「定理成立」之间隔着一步，这一步叫「有人读懂了」。历史上形式化证明出过「命题形式化错了但证明正确」的先例，所以社区核验的重点其实是**形式化陈述本身是否忠实于原命题**。这也是陶哲轩保留的原因。对普通人，最有用的一个判断是：**如果连数学家都要读很久，那「AI 独立做研究」这件事在 2026 年仍然是「能做，但需要人类验收」。**

做法：想跟这个话题，别用「AI 证明了黎曼猜想」当标题，会被打。可用的角度是「编译器通过了，数学家还没通过」——三个平台的榜单都在等这个解释，而知乎那条「高估了难度」的热榜说明受众更关心「是不是我们一直想复杂了」，不是「AI 多强」。

⚠️ 社区声明的核验范围（是否覆盖全部引理、是否引入未声明公理）需查原文，本刊未见全文；「1,700 万行」为公开报道口径；克雷官网状态为 11/23 抓取；丘成桐、陶哲轩表述为公开观点，非评审结论。

源：Lean / Mathlib 社区联合声明（经 AI 日报 11/23 汇总）、知乎热榜 11/23、抖音热榜 11/23、克雷数学研究所官网

**2. 百万粉主播私闯果园、切开一千多斤苹果扔地上，只愿赔 6000 元**

起因：一名百万粉主播未经许可进入果农果园直播，直播中**切开一千多斤苹果扔在地上**。经过：果农称损失一千多斤，对方只愿赔 **6,000 元**，果农不接受并报警；乡里介入调解。11/22–23 事件冲上微博热搜（相关话题热度 140 万 + 114 万，「主播糟蹋千斤苹果仅赔6000元」「私闯果园主播下架所有视频」），该主播账号在各平台**已下架全部视频**，疑似自行删除或被平台处置。后续又出现一次反转：主播方面改口称「系找错地点」，与此前「未打招呼」的指控各执一词，事件仍在调查。

判断：这类事件的价值不在道德谴责，在**「损失怎么算」这个技术问题**。一千多斤苹果，按地头收购价、按零售价、按「预期收益」算，是三个数量级不同的数字。律师口径是「赔偿以实际损失为准」——而实际损失需要举证，果农最难举的恰恰是证据。所以「只赔 6000」不是终点，是双方对「一斤值多少钱」没有共同基准。

做法：这跟做内容的人有一条直接关联——**商业拍摄进场地、进果园、进店铺，先签一页纸**：拍摄范围、可动用的物料、损耗怎么赔、素材能不能商用。一页纸能省掉后面所有纠纷。同理，如果你在拍短剧外景，场地协议里加一句「因拍摄造成的物品损耗按采购价赔偿」。

⚠️ 6,000 元为果农单方表述，未见调解结果；「找错地点」为主播方说法，与果农说法冲突，尚无定论；账号「下架全部视频」可能为主动删除，不必然是平台处罚。

源：微博热搜榜 11/22–23、人民网转述、小今热榜 11/23

**3. 问界 M9 车主开着辅助驾驶在高速上熟睡，客服回应「ADS 只是辅助」**

起因：一段行车记录仪视频流传——一名疑似问界 M9 车主在高速开启辅助驾驶后，**直接躺在主驾位置熟睡，车辆保持上百公里时速自主行驶**，全程未接管。发布者配文还带着炫耀语气（「出差回程太累了直接倒头就睡，全程靠智驾开回武汉」）。经过：视频发酵后冲上微博热搜前列，发布账号（网名「涛哥」、ID Tao186588）在各大平台**已无法检索**，疑似自行删除或被封禁。当前状态：问界官方客服回应称已完整记录、转交专项团队跟进核实，并重申 **ADS 高阶智驾「仅为辅助驾驶而设计，不是自动驾驶或无人驾驶」**，全程必须手握方向盘、随时接管。

判断：这条把一个长期被营销语言模糊的边界摆到了台面上——**L2 的责任在驾驶员，但你买到的是一个长得像 L3 的体验**。真正的分歧不在技术，在预期管理：当系统能连续几百公里不接管，人的注意力必然衰减，而法规仍要求你随时接管。这个矛盾不会因为一次热搜解决。

做法：如果你车上有高阶智驾，去设置里把「脱手检测」和「注意力监测」调到最严，别关。更实用的一条：把「智驾状态下我也要看着路」写进家庭规则，尤其是长途。这不是技术问题，是习惯问题。

⚠️ 车型为「疑似问界 M9」，未见官方确认当事车辆；视频真实性由平台传播，未见交管部门通报；账号消失原因不明；客服回应为媒体转述。

源：微博热搜榜 11/23、快科技 11/23

**4. 「幼儿园要招 2 岁孩子了」冲上百度热搜第一**

起因：多地幼儿园开始下探招收 **2 岁幼儿**（开设托班），话题在 11/23 冲上百度热搜第一（热度 781 万），微博同题 57 万。经过：讨论迅速分成两派——一派认为是「生源减少、幼儿园抢孩子」，另一派指出这是托育位长期不足的补位（2–3 岁是托育需求最集中的年龄段，而幼儿园有场地、有资质、有师资）。当前状态：仍停留在话题讨论层面，未见统一政策口径；各地做法不一，有的明确是「托幼一体」，有的只是暑期托管延伸。

判断：这件事的本质是**两套系统的接口在重连**——幼儿园（3–6 岁，教育局管）和托育（0–3 岁，卫健委管）过去是两条线，现在因为一边缺生源、一边缺托位，开始互相借资源。对普通家庭，短期内的真实变化不是「能送 2 岁了」，而是「送进去的是托班还是小班、收费按哪套标准、老师有没有托育资质」——这三件事决定它是不是真的解决问题。

做法：如果家里有这个需求，问三个问题再交钱：① 这个班在教育局备案是「托班」还是「小班」；② 师生比是多少（托育通常要求比幼儿园更严）；③ 老师有没有育婴师/保育员证。三个问题问完，基本能筛掉「拿小班名额当托班卖」的那批。

⚠️ 「多地」为热搜话题归纳，未见统一文件；781 万、57 万为热搜热度值，不代表支持率；「生源减少」为讨论中的归因，未引官方数据。

源：百度热搜榜 11/23、微博热搜榜 11/23

## 三、潜在挣小钱的机会

**1. 不是「做产品」，是「先搬出子域名」：13,700 家 Stripe 验证收入的公司里，还挂在 lovable.app / replit.app 子域上的只有 6.8% 挣到过钱**

路径：BigIdeasDB 2026 年 11 月的分析，把 TrustMRR 上 **13,700+ 家**有 Stripe 验证收入的公司，与其域名后缀、AI 品类、买家类型做了匹配。核心对照表只有两行：

| 分组 | 公司数 | 有月度收入的比例 | 挣钱者中位 MRR | 达到 $1K+ MRR |
|---|---|---|---|---|
| 仍挂在 vibe-coding 平台子域 | 177 | **6.8%（12 家）** | **$54** | **0 家** |
| TrustMRR 其余全部 | 12,200+ | **39.9%** | **$115** | 950+ 家 |

同一份数据里，436 家通过 lovable.app / replit.app / vercel.app / netlify.app 子域收款的公司，只有 **6 家（1.4%）**被归为「established business」，而全库 30,000+ 家里这个比例是 **24.6%**；子域组超过 30% 是 micro SaaS，全库只有 6.6%。2026 年 9 月版本的同一研究给出近似结论（7.6% vs 43.5%，最高 $155）。

反面对照的真实样本：Kolbo.AI（用 Lovable + Cursor + Claude Code 搭的一体化创意工作台）**近 30 天收入 $113,859、MRR $48,223、748 个活跃订阅、累计 $446,995**，Stripe 经 TrustMRR 验证，截至 11/21。

月收入换算：Kolbo 的 $113,859（30 天流水）÷ $48,223（MRR）≈ **2.4 倍**——差额不是增长，是**一次性收入**（年付、加购额度、一次性买断）。所以看这类项目的 MRR 要高估它的稳定性：把「流水」当「月收入」会高估一倍以上。

判断：这份数据最容易被误读成「搬个域名就能赚钱」，实际因果是反的——**是先挣到钱，才会去搬域名**，留在子域上的是没走到那一步的那批。但它仍然给了一个可执行的动作：子域名是「没认真」的外部信号，用户、支付方、合作方都会拿它当判断依据。而 $54 与 $0 这两个数字说明的另一件事是：**vibe coding 降低的是「做出来」的成本，没降低「有人付钱」的成本**——12 家里最高的一家月入 $99。

做法：今天做三件小事，成本接近零。① 有自己域名但还在用平台子域访问的，做 301 跳到主域，**别只改链接**；② 支付页、邮件模板、退款政策页的域名统一；③ 在 Product Hunt / 应用商店的落地页上，把「Powered by xxx.app」那块去掉。三件事加起来 1 小时，属于「不做也没损失、做了别人才当你认真」的那类。

⚠️ 相关性不等于因果：子域组是「被筛剩下的」，很多正经项目起步也在子域、挣钱后才迁移；「0 家达 $1K」是快照，样本仅 177 家；TrustMRR 是创始人自愿接入支付的样本，天然偏向有东西可展示的人；Kolbo 的 $113,859 与 $48,223 为平台口径，未拆分一次性与订阅收入。

源：BigIdeasDB 2026-11 分析（经 todayonlinenews 11/23 转述）、TrustMRR、MissumAI 榜单

**2. 一个人做「无脸短视频自动生成」，6 个月做到 $40,000 MRR、月成本约 $10,000、利润率 75%**

路径：独立开发者 Eric Smith 自己运营几个无脸解说类短视频号，痛点是「写脚本、配音、配画面、定时发布」全手动。做法是反过来——不做一个大而全的剪辑软件，只跑通一条**单点闭环**：用户填一个提示词，几分钟内拿到可直接排期的成片。技术栈没有自研视频大模型，用全栈 Web 框架把主流 LLM 写稿接口 + Replicate 图像动画 + 合成语音串起来。节奏：2 月 1 日拿到第一个付费用户，2 月底到 $1,000 MRR，之后几个月从 $2,000 冲到 **$40,000 MRR**。增长的关键动作是**联盟返佣**——最早那批付费用户本身就握有成熟账号，会主动录屏演示「怎么用它批量更新」，他把这些口碑转成持续的新增订阅。

月收入换算：$40,000 MRR，月总支出约 $10,000（云主机 + 模型调用 + 早期买量），毛利润率约 **75%**，未融资。

判断：这条的可复制部分不在技术栈，在**「用户本身就是渠道」这个结构**——他卖给的是一群已经有受众的人，所以产品演示即获客素材。这跟 11/21 期那个「8 个客户 $4,917」的样本正好相反：那个是高价低频、靠销售；这个是低价高频、靠自传播。做短剧的人对这条会更有感觉：你的投放素材本身就是产品演示。

⚠️ 风险四条：数据源自 MRR Story 的编辑整理，**未经独立审计**，也未在 TrustMRR 上做支付验证；依赖 Replicate 等第三方算力，上游涨价直接压毛利；「无脸短视频」这条赛道门槛低，同类工具正在快速增加；75% 毛利未计创始人自己的时间成本。

源：MRR Story 案例整理（经网易 11/23 转述）、AutoShorts

**3. 把 5 个生成模型塞进一个「比稿」入口：$48,223 MRR、748 个订阅、均价 $64**

路径：Kolbo.AI 是一个一体化创意工作台，用 Lovable + Cursor + Claude Code 搭出来——这点本身值得记，因为它是「vibe coding 天花板样本」：同批 177 家子域公司里，最高的一家月入 $99。它的分发靠的不是投放，是 **MissumAI 排行榜第一名**带来的自然流量。数据（TrustMRR，Stripe 支付验证，截至 11/21）：**MRR $48,223、748 个活跃订阅、近 30 天收入 $113,859、累计 $446,995**。

月收入换算：$48,223 ÷ 748 ≈ **$64.5/订阅/月**；$113,859 ÷ 748 ≈ **$152/订阅/30 天**——单月人均付出是 MRR 均价的 2.4 倍，说明**大部分收入来自一次性加购或年付**，不是纯订阅。

判断：这类「创意工作台」的护城河很浅（功能都能被复刻），真正的资产是**排行榜位次 + 748 个愿意加购的用户**。它的收入结构（订阅打底、加购扛量）值得抄：纯订阅制会把高用量用户挡在外面，加购额度能把这批人的付费意愿榨出来。对短剧团队，同一套结构可以直接用在「按集计费 + 月度保底」上。

⚠️ 风险四条：$113,859 与 $48,223 的口径差未被官方解释，本刊按「一次性 + 订阅」推定，属推断不是披露；数据来自第三方分析转述，未见 Kolbo 官方确认；一体化工作台赛道竞争极激烈（Cursor、Lovable 自身在向上延伸）；排行榜分发不可复制，位次会掉。

源：BigIdeasDB / todayonlinenews 11/23（引 TrustMRR、MissumAI）、Kolbo.AI

## 四、小而美产品

**HKUDS/CLI-Anything（主推·给任何软件生成一套命令行，让 agent 能直接调用它）**
- 是什么：把「软件给人类用」改成「软件给 agent 用」。一条命令为任意软件生成 CLI，输出 JSON + 人类可读双份；配 CLI-Hub 包管理器（`pip install cli-anything-hub` 后 `cli-hub install <name>`）浏览、安装、管理社区已建好的 CLI；提供 7 阶段生成器（分析源码 → 设计命令结构 → 实现 → 测试 → 发布）。**63,124 stars、5,739 forks、286 个 open issue、Apache-2.0、2026-03-08 建仓、11/20 最后提交、组织账号（HKUDS，香港大学数据智能实验室）、2,461 个测试通过、18 个应用 demo、有 arXiv 技术报告**
- 差异化：市面上多数「agent 工具」是给 agent 加能力，它是**给存量软件加接口**——两者方向相反。18 个 demo 覆盖 CAD、3D 场景、图表、字幕、游戏，都是「有 GUI、没 API」的那类软件；对 agent 生态来说，这补的是最难补的一块（不是模型不够聪明，是软件没有入口）
- 用在哪：短剧流水线里那批「只能手点」的环节——批量导出、批量改名、按集生成字幕、Excel 报表合并、素材去重——都可以先生成 CLI 再接进 agent，跑长任务时不用守着界面；也能把公司内部工具（审核台、素材库）接进 MCP，让 agent 直接查
- ⚠️ 生成质量取决于软件本身有没有可分析的源码或稳定 GUI，闭源重型软件常需手写适配；286 个 open issue 说明适配层还在快速迭代；「2,461 个测试通过」是项目自报口径，未第三方复验
- 源：GitHub HKUDS/CLI-Anything（11/23 实测 star / fork / 提交时间 / Apache-2.0）/ hkuds.github.io/CLI-Anything

**bookwjitchieni1986/blender-ai-mcp-addon（主推·给 Blender 装个 AI 副驾，用说话改场景，还带 MCP server）**
- 是什么：面向 Blender 4.2+ 的 AI 助手插件 + 内置 MCP server。能检查场景与对象、建物体、改材质、找资产、做多步工作流；带一个可视化 Studio 工作台（对话 + 场景对象 + 视口快照 + 审批 + 任务板）；模型可接云端各家、本地 Ollama 或自定义 endpoint；**21 个场景工具**；支持「单助手」直连或「Manager → Workers → Reviewers」任务链（按序执行、失败只给一次修正机会）。**2,760 stars、39 forks、61 个 open issue、MIT、2026-11-19 建仓、11/22 最后提交、个人项目、Windows x64 有发布包**
- 差异化：多数 Blender AI 插件停在「生成一个模型」，它的落点在**「改现有场景」**——先读场景再动手，这是实际生产里 80% 的工作；MCP server 是内置的，别的 MCP 客户端（OpenCode 等）能直接连进来，不用再写一层桥
- 用在哪：AI 漫剧里的 3D 场景搭建（同一办公室/街道复用、换材质换光）、分镜预演（先用低模摆机位，再决定哪几个镜头值得生成）、道具批量化（一次性摆 20 个同款货架）
- ⚠️ 建仓仅 4 天，属极早期项目，别放生产主链路；61 个 open issue / 2,760 stars 的比例说明关注度高但打磨不足；Windows 发布包未经代码签名，装的时候要手动过 SmartScreen；「21 个场景工具」的实际覆盖度需按你的场景自测
- 源：GitHub bookwjitchieni1986/blender-ai-mcp-addon（README 与 11/23 实测数据）/ mcp-for-blender-pro

**sybil-solutions/inference-optimisation-skill（备选·把「本地大模型调参」从玄学变成爬山流程，带实测数据）**
- 是什么：一个 agent skill（Claude Code 及任何加载 `SKILL.md` 的 agent 可用，也可照 `PROMPT.md` 手动跑），把本地 LLM 推理提速写成六步流程：先算理论上限 → 一次只改一个变量 → 对照交错测量 → 记录包括失败在内的每个结果 → 用长上下文检索做门禁 → 合格后固化版本再发布。覆盖单用户/并发解码、投机解码、prefill、KV cache、启动时间与首 token 延迟。**2,021 stars、189 forks、20 个 open issue、MIT、2026-11-16 建仓、同日最后一次提交、组织账号**
- 差异化：它不是「flag 清单」，是把**上限计算**放在第一步——先告诉你这个硬件上的目标是不是超过物理极限，再让你动手调。README 里给了完整实测表（Intel Arc B390 iGPU 解码 43.6→53 tok/s、prefill 256K 297→628 tok/s；RTX 3090 上 Qwen3.8-27B EXL3 3bpw + MTP 达 96.2 tok/s；4×H200 上 DS V4.1 Flash 从负载崩溃到 229.1 tok/s）
- 用在哪：你有 4060 Laptop 8G + 16G 内存，本地跑模型最大的浪费是「拿别人的参数配置硬套」。用它跑一遍流程，先算出你这张卡的理论上限，再决定要不要继续折腾——很可能结论是「这个模型在 8G 上就是跑不动」，那比调三天参数更有价值
- ⚠️ README 的实测全部在 Intel Arc / RTX 3090 / H200 上，**没有 4060 Laptop 的数据，不要假设可以线性折算**；建仓 11/16、最后提交同日，属单次提交，后续是否维护未知；MIT 可商用，但流程本身要你提供可测量的环境（能跑 benchmark、能改启动参数）
- 源：GitHub sybil-solutions/inference-optimisation-skill（README 实测表与 11/23 仓库数据）
