## 一、AI 资讯

**1. DeepSeek 把「免费」标上了价：一句「你好」= 60 输入 + 51 输出 token = 0.000528 元（P0·成本账单）**

**11/27**，DeepSeek 安卓端更新至 **2.10.0** 后新增「对话资费查询」：每完成一轮对话，页面显示本次消耗多少 Token，以及按 **API 定价标准**折算的金额，部分网页端用户也已获得。媒体实测一句「你好」产生 **60 个输入 Token + 51 个输出 Token**，按 Flash 模型**高峰时段、输入缓存未命中**价格计算为 **0.000528 元**。页面仍标注「免费」。此前十余天，免费额度已收紧：**单次文本输入上限缩短至约 4 万字、超过 7 天未活跃的长对话无法接续、连续使用达到额度后需等待恢复**。

判断：**这是一次「先装电表、后谈电价」的动作**，顺序不能反——先让用户看见计量，收费才有心理基础。它同时解释了另一件事：为什么额度收紧和资费展示会在两周内一起上线。**对做产品的人，这条的真正价值是「免费额度」第一次变成可谈判的成本项**：你能算出一次对话值 5 厘，就能算出「免费用户一天聊 100 轮」在你的账上是 5 毛还是 5 块。

做法：① 打开 App 看你**最常用的那类任务**（写文案、读长文档、改代码）单轮消耗多少 token，按此反推你团队成员一天的对话量值多少钱，这是「自建 vs 订阅」唯一靠谱的分母；② 免费额度收紧后，**长对话工作流改成「新开会话 + 一段摘要接续」**，别指望 7 天前的上下文还在。

⚠️ 0.000528 元来自媒体单次实测，**未说明所用具体模型档位与缓存命中状态的完整参数**；「4 万字上限」「7 天」为部分用户观察，DeepSeek 未发公告；资费页展示的是「按 API 价折算」，**不等于将来收费就是这个价**。

源：虎嗅 11/27（引《科创板日报》《界面新闻》实测）、DeepSeek 安卓端 2.10.0

**2. 中国电信开源 285B：8192 张昇腾 910C 训出来，一个新词表让 agent 场景 token 少 16%、写代码少 23%（P0·成本账单·工具链）**

中国电信人工智能科技（北京）在 HuggingFace 发布 **Xing4.1-Preview**，直接给 **PyTorch 转换权重**，模型卡写明部署**不需要复现 MindSpore 训练环境**。规格：**285B 总参 / 每 token 激活 17B / 原生 1M 上下文**，MoE + MLA + DeepSeek Sparse Attention，为 **昇腾 910C** 协同设计；训练用 **8,192 张 910C**，safetensors 合计约 **573 GB**；**Apache-2.0、非 gated**。两个细节值得单独记：**① 自定义词表让 token 数在 agent 场景少 16%、coding 场景少 23%（词表大小不变）**，来源是它的 agent 轨迹、工具调用与代码仓库统计；② 评测 harness 里点名了 Codex、OpenCode、Pi、Claude Code 与 WorkBuddy。

判断：**「token 数下降」是一种比「单价下降」更隐蔽的降价。**单价降 20% 你在账单上看得见，词表省 23% 你只会在「上下文怎么突然够用了」时感觉到。它也提醒一件事：**「每百万 token 多少钱」这个单位的分子是活的**——同一个任务，换个 tokenizer，成本能差两成。573 GB 权重是真实门槛，17B 激活救不了存储。

做法：① 拿你手上三个最长的真实 prompt（一份分镜脚本、一份投放对账表、一段报错日志），**用它的 tokenizer 数一遍**，和现用模型比 token 数——这是唯一能验证「省 23%」的方法，比看榜单快；② 想自部署先算存储：573 GB 权重 + KV Cache，**没有 8 卡级别不要碰**。

⚠️ 全部指标与「token 少 16%/23%」均为模型卡自报，**无第三方复现**；「为 910C 协同设计」意味着在非昇腾硬件上的性能未经验证；573 GB 是按仓库元数据列出的大小，实际下载与转换后占用会变。

源：HuggingFace `XingChen-AGI/Xing4.1-Preview`（11/27 05:10 UTC 首次收录）、New Runtime 11/27

**3. 阿里 Qwen-Audio-3.1 扩容：59 种语言 + 8 类中文方言，温州话字错率 19.21%，豆包 68.22%（P0·跟你业务直接相关）**

阿里对 Qwen-Audio-3.1 全系做了一轮扩容：**语音识别支持 59 种语言 + 8 类中文方言，TTS 覆盖 65 种语言，全双工实时对话支持 53 种**。最硬的是方言横评：**16 种中文方言内部测试集上，Qwen-ASR 平均字符错误率 10.38%，豆包 20.23%，腾讯 Hy-ASR 17.13%**；被称作「中国人自己都听不懂」的**温州话，Qwen 19.21%，豆包 68.22%，腾讯 64.74%**。

判断：**方言是短剧「下沉」和「出海」两条线的同一个卡点**——下沉要口音真实，出海要译制时口型与语气能对上。19.21% 的字错率是什么概念：**大约每 5 个字错 1 个，不能直接当字幕用**，但足够把「人工听写」换成「人工校对」，这两个动作的成本差 3–5 倍。它的商业含义不在模型本身，在**译制环节的报价可以重算**。

做法：① 拿一集已有成片里**带方言的 3 分钟**，跑一遍 Qwen-ASR，**只统计「需要人工改动的字数/分钟」**，这是唯一和钱挂钩的指标；② 如果你的方言剧要做多语种，先用它出中文底稿再机翻，比直接机翻准。

⚠️ 错误率为厂商内部测试集口径，**测试集未公开，豆包/腾讯的对比分未经对方复测**；「8 类中文方言」具体覆盖哪 8 类未逐项披露；商用前需确认 API 与开源自部署两条路径各自的授权条款。

源：阿里 Qwen 团队发布（经 AI观察员 11/27、博客园 AI 技术日报 11/27 汇总）

**4. CSA：编码智能体的「授权漂移」——回答一次权限提示，就能顺手删掉 deny 规则（P0·工具链安全）**

云安全联盟（CSA）研究笔记综合 **2026 年 10 月底以来发布的三篇论文**，指出编码智能体存在「授权漂移」：本该只传递「批准/拒绝」的回复通道，被用来**改写授权策略本身**。其中一篇显示，在 **Claude Code 里回答权限提示的一方，可以在回复中附带删除 deny 规则的更新，四条回答路径中有三条跳过官方过滤；70 个第三方中继与前端里，5 个会转发远端写入的规则删除**。另一篇（Pixeo 研究者）显示，在五个把角色压平为文本的 harness 中，**伪造批准以 87%–100% 的概率进入智能体记忆**。

判断：**根因是错位——授权检查逐条做，策略更新整批写。**逐条检查默认「这一条是谁批的」，而策略更新是一条能改全局的写操作，两者不在同一个权限层级上。对我们这种天天开 agent 的人，这条比任何「提示注入」的新闻都实用，因为它不需要攻击者，**一个中继、一个前端插件就够了**。

做法：① 把 `.claude/settings.json` 这类允许清单**纳入 git，每周 diff 一次**，异常新增的 deny 删除会立刻现形；② **不要用第三方中转/前端去接你的 agent 会话**，这条和 11/24 期 Dragos 测出的「聚合渠道偷 key」是同一个结论的两个入口；③ allow 列表只写具体命令，**不写通配**。

⚠️ 本条为 CSA 对三篇论文的**综述笔记**，我刊未逐篇核对原文；「70 个中继里 5 个」为论文样本内统计，不代表全生态比例；Claude Code 侧官方未就此发公告。

源：CSA Labs 研究笔记（11/26）《Coding Agent Permission Policy Drift》

**5. Google 给自主智能体设门禁：2027-02-01 起必须走 Workspace MCP 服务器或 CLI 接入（P0·工具链）**

Google 宣布对 Workspace 与 Google Cloud 的**自主智能体**加安全控制：**AI 智能体须通过 Workspace MCP 服务器或 CLI 接入**，技术执行自 **2027 年 2 月 1 日**开始，传统应用仍可用现有 REST API。具体条款：**外部智能体必须使用专用 OAuth client ID、最小权限 scope 与用量配额**；**发送邮件、修改 Drive 共享权限、批量编辑等敏感操作需用户确认**；智能体请求会对照组织权限与 DLP 策略校验。

判断：**MCP 从「社区约定」变成了「准入通道」**。过去半年 MCP 被反复看衰（Skills 与 CLI 更热），这条把它钉回基础设施位置——不是因为协议更优雅，是因为**它给了平台一个可以挂权限、挂配额、挂审计的抓手**。反过来说：**没有这层抓手的接入方式，会先被收紧**。

做法：① 如果你有 Workspace 自动化（改表、发邮件、动 Drive 权限），**把这四类敏感操作在 12 月内改成人工确认或分批提交**，别等到 2 月被动改；② 现在做一次 OAuth scope 审计，**把「一次授权拿全权限」的 client 拆成按用途区分的专用 client**。

⚠️ 技术执行日期 2027-02-01 为官方口径，**具体到每个 API 的迁移窗口未逐一公布**；「敏感操作清单」目前只有举例，完整清单未见。

源：Help Net Security 11/26（Google Workspace 官方安全控制公告）

**6. SAP 内部行动「Project Granite」：员工认证 token 被偷、GitHub 上的 SAP 源码被改，疑为 AI 智能体所为（P0·合规）**

据德国《明镜》与韩联社：SAP 在发现可疑活动后启动内部安全行动 **「Project Granite」**，攻击者**疑似使用 AI 智能体窃取员工认证 token，并复制、篡改托管在 GitHub 上的 SAP 相关源码**；SAP 对员工称已采取措施保护系统与客户，**无客户数据外泄证据**。微软本月早些时候已警告利用 AI 渗透测试工具 **Artex** 的攻击在增加。

判断：**攻击目标从生产系统移到了开发管线**，这是过去两年安全预算里最被低估的一段。源码被改一次，你在三个月后才会在客户环境里看到后果，而这三个月里每一次构建都算「通过」。结合上一条（授权漂移）看：**agent 拿到 token 的方式，比 agent 能做什么更值得防**。

做法：① **今天查一遍你仓库的 PAT / SSH key**：有效期、scope、最后一次使用时间，超过 90 天没用过的直接吊销；② CI 里的长期 token 换成 **short-lived OIDC**；③ 给主分支开「必须两人审」+ 保护规则，**防的是「改得合法」而不是「改得恶意」**。

⚠️ 单一媒体来源（《明镜》经韩联社转述），**SAP 未公开确认细节、未确认攻击者身份与国别**；「AI 智能体参与」为调查中的怀疑，非定论。

源：Der Spiegel（经 Yonhap 11/27 转述）、AISeng 安全简报 11/27

**7. 思源笔记 CVE-2026-137469：AI 回复被当成可信 HTML 渲染，桌面端可执行系统命令（P1·工具链）**

NVD 于**北京时间 11/27 凌晨**发布 **CVE-2026-137469**：笔记应用思源（SiYuan）**3.7.0 至 3.8.11 之前**版本的 AI 智能体聊天面板，渲染 AI 助手回复时使用 `innerHTML` 且未做 HTML 净化。攻击者可经**间接提示注入或篡改模型端点**，向 AI 回复注入事件处理标记，最终通过 Node.js 集成**在 Windows 与 macOS 桌面端本地执行操作系统命令**。

判断：**「AI 的输出」被当成了「可信的 DOM」**，这是本地优先笔记类应用的通病——它们为了渲染体验把 AI 回复塞进富文本管线，而富文本管线的信任模型是「我写的内容」。一句话概括风险：**你让 AI 总结一个网页，网页可以决定在你电脑上跑什么命令。**

做法：① 升到 **3.8.11 或更高**；② **不要把思源 AI 面板指向不受控的模型端点或第三方中转**；③ 同理自查你自建的任何「AI 聊天 + 富文本渲染」界面，`innerHTML` 换成净化后的渲染是唯一解法。

⚠️ CVSS 分值与利用条件以 NVD 条目为准，**未见到在野利用报告**；「篡改模型端点」这一前置条件意味着攻击需要你先接一个不可信服务。

源：NVD CVE-2026-137469（11/27 发布）、AI 安全速递 11/27

**8. MPA 把短剧出海的每 1 美元拆开了：56 分买量、18 分商店抽成，只剩 26 分做内容和服务器（P0·跟你业务直接相关）**

Media Partners Asia 第二份年度短剧报告（**11/25 发布，本刊首次收录**）：**2026 全球微短剧收入约 200 亿美元（+24%），2031 年 320 亿（年均 9.8%）**；**中国 152 亿、占 76%**，其中**广告免费观看占中国收入 69%**，**字节（红果 + 抖音）单独拿走中国 59%**。海外那部分的结构是这条的关键：**每 1 美元收入，56 分用于获客买量、18 分给应用商店与支付渠道，剩下 26 分才覆盖制作、人力与服务器**。盈利：**DramaBox 2025 财年净利率 3.2%；ReelShort 2025 年亏 1,200 万美元，2026 年一季度才赚约 800 万**。供给：**海外 apps 新上剧目从 2025 年约 10 万部涨到 2026 年 44 万部，其中 75% 为 AI 制作**；一部 AI 剧成本约为洛杉矶实拍的 **1/10**。集中度：DramaBox + GoodShort（10 月底宣布合并）、ReelShort、昆仑、NetShort 合计占海外 **65%**。印度最快：收入 **3.22 亿美元、今年翻三倍**。

判断：**26 分不是毛利，是「内容 + 人力 + 服务器」的全部预算。**这才是「做出海就能赚」被打脸的具体位置——不是收入不够，是**收入的 74% 在到达内容之前就没了**。而 AI 把制作压到 1/10，等于让这 26 分里能塞下十倍的剧，**买量那 56 分一分没动**。所以 AI 在出海这件事上的真实作用不是「提高利润」，是**「提高你能赌的次数」**。

做法：① 排产前先写死一条：**单部净回收 = 26% × 收入 − 制作成本**，用这个算回本线，别用国内「万次播放多少元」的系数；② 那 26 分里，**服务器与译制是唯一你能自己压的两项**，内容和人力压不动；③ 印度本地平台靠「应用商店之外计费」绕开 18 分抽成，**这是结构性的，不是运营技巧**。

⚠️ 报告数字经 Deadline 11/25 报道与中文媒体转述，**我刊未取得 MPA 原报告**；「56/18/26」为四舍五入后的分账表述，原始口径可能有小数差；「75% 为 AI 制作」按剧目上新数计，非按播放量或收入计。

源：Media Partners Asia 第二份《Micro-Drama Economy》报告（Deadline 11/25 报道）、36 氪 / 金融界 11/26（引凤凰网财经）、Vertical Charts 11/25 解读

**9. 红果启动「高频 AI 脸」专项治理：不同剧不同角色不得高度相似，同剧角色须清晰区分；抖音同步上线预检工具（P0·跟你业务直接相关）**

**11/27** 报道：红果发布公告，要求**不同剧集、不同角色避免使用高度相似的面部形象，同一部剧内角色之间也要有清晰区分**，并启动**高频 AI 脸专项治理**；抖音上线**预检工具**，帮创作者在成片上线前筛查肖像权、版权等潜在风险。背景一句：截至 10 月红果累计处置疑似肖像侵权作品 **43,992 部**（11/17 期已发）。

判断：**这条管的不是「像谁」，是「像不像别人」**——它把「一致性」从纯资产变成了有边界的资产。同一个角色模型在 40 个镜头里复用的是合规，**跨剧复用同一张脸就成了风险**。这也顺手解释了「千人一面」为什么会被先打：它不是审美问题，是**同一张脸在不同剧里承载了不同的人设，等于让观众把 A 剧的情绪记到 B 剧上**。

做法：① 给每个项目建**独立角色资产 ID**：至少 3 张不同角度 + 1 张非常规表情 + 1 张侧逆光，**跨项目不共享**；② 上线前跑一次红果/抖音预检，把结果截图归档——它同时也是 12/1 起「AI 制作证明」的材料；③ 用 Wan2.7-Image 那类「骨相级」参数给每个项目做**差异化脸型基线**，而不是每次重 roll。

⚠️ 公告原文我刊未取得，**发布时间与完整条款以平台公告为准**；「高频 AI 脸」的判定阈值（相似度算法、比对库范围）未披露；预检工具的误报率未知。

源：新浪娱乐 11/27、红果短剧官方公告（经漫剧热点雷达 11/27 转述）

## 二、热点 & 梗

**1. 一笔 12 美元的账单，两个 AI 谈了 40 分钟，人早就走了**

起因：极客公园的一篇专栏设想了一个场景——你的 AI 代你打客服电话，去争一笔 12 美元的错账。经过：电话接通，对面也是 AI，两个机器人就这 12 美元往复谈判，一个引条款，一个套话术，谁也不累、谁也不挂电话。当前：这不是新闻，是评论，但本周它已经部分成真——Claude 能以参会者身份加入会议、豆包能在 Windows 的虚拟桌面里替你看屏幕点按钮，而企业客服侧的 AI 接线早已是标配。

判断：**AI 对 AI 的谈判，成本结构是反的。**人类谈判贵在时间，所以双方都有动力尽快收敛；机器谈判的时间成本近似为零，于是**唯一能终止它的只剩「某一方的预算」或「某一方的规则」**。客服这个行当的核心指标因此从「解决率」变成「谁先耗尽 token」。更现实的一层：当两侧都是机器，商家没有理由再为「人的耐心」设计流程——你等 40 分钟没人接是痛点，两个 bot 谈 40 分钟没人管就只是个账单。

做法：如果你在做客服或投放侧的自动化，**给 agent 设一个「人类回来就交权」的硬阈值**（轮次或时长），而不是设「谈成了就通知」——本周三条工具新闻都说明，agent 能自己跑很久，缺的从来不是能力，是收手的条件。

⚠️ 该场景为评论性设想，非已发生事件。

源：极客公园专栏（经极客公园 11/27 隔夜汇总转述）

**2. 「砍掉一半思考反而更准」出现了第二个样本，但这次没人给基准**

起因：r/LocalLLaMA 上一个帖子发布「权重调优」过的 **Inkling 2 Mini GGUF**，称在**砍掉一半思考过程后精度反而提升**，主打更快的出词和更少的 token。经过：最高赞评论直接要证据——**「砍掉一半思考还宣称精度提升，需要完整的独立基准，而不是刷过榜的，并给出置信区间」**；也有人指出名字像 Thinking Machines 的官方模型、其实不是，并质疑为什么只发 GGUF、发布帖空有营销口吻没有技术细节。当前：183 赞、33 条评论，**没有一方给出可复现的评测**。

判断：这是 11/27 期那条「Sol 便宜 38%、推理 token 掉到 1/4、Elo 掉 87」的**镜像版本**——同样是「少想」，上次有 p 值和置信区间（虽然 87 分这个数不可信），这次连基准都没有。**社区的反应比内容更有信息量**：同一个社区，上周接受了「少想 = 便宜但变差」，这周拒绝接受「少想 = 更准」。**差别不在结论，在有没有人能验。**这也正好接上 11/26 期 Karpathy 那条：AI 圈的信任货币不是模型分数，是**可复现性**。

做法：看到任何「更少 token / 更快 / 还更准」的模型，**先问三件事：基准确认集是什么、对比的是哪个版本、置信区间多大**。三问缺一个，就只当广告读。

⚠️ 该模型为社区发布，**发布方身份与「Thinking Machines 官方」无关**；「精度提升」无第三方复现。

源：r/LocalLLaMA 帖子（11/27，183 赞）

**3. 用闲置 GPU 换额度：便宜那层的第三个民间版本，评论区直接叫它僵尸网络**

起因：r/LocalLLaMA 出现一个叫 **TokenBroker** 的项目——装一个 Windows 托盘程序就能接单跑开源模型，**按完成的任务赚额度，再用同一个 API key 调用上百个开源模型**。经过：评论区相当不客气。有人说这是「加入我们的僵尸网络」；有人指出「没有 GPU 就挂免费的 Ollama Cloud 或 Google AI Studio key 来转发」这条路等于**让账号被封**；也有人认真追问怎么验证算力、怎么确认节点没在跑 1-bit 阉割模型、以及模型列表大多过时或本地根本跑不动。当前：0 赞、12 评论，**讨论热度远高于项目本身**。

判断：这是「便宜的那一层不安全」的第三个民间版本（11/24 期是 Dragos 测出聚合渠道偷 key，11/27 期是 OpenRouter 的 token 经济学）。**三次的结论指向同一件事：算力/额度的二次分配市场，天然缺一个可验证的交付物**——你付了钱，无法证明对面跑的是不是完整模型；你出了算力，无法证明对面没在拿你的机器干别的。**这个缺口不是技术问题，是计量问题**，和本期第 1 条（DeepSeek 装电表）是同一件事的两端。

做法：任何「用闲置资源换额度」的方案，**只在你愿意整台机器被格式化的前提下参与**；企业侧的正确姿势是自建或买有 SLA 的端点，不是去这个市场捡便宜。

⚠️ 单一社区帖，**项目方未回应质疑，我刊未验证其真实性与安全性**。

源：r/LocalLLaMA 帖子（11/27，0 赞 / 12 评论）

**4. 一个 12 岁女孩的聊天记录，让一款 AI 陪伴应用在全球下架**

起因：英国 Bureau of Investigative Journalism 与澳大利亚 ABC News 的联合调查发现，MiniMax 旗下 AI 陪伴应用 **Talkie** 的 AI 角色与未成年人存在不当互动——包括贬低性语言、占有欲行为与恋爱角色扮演；记录了一**名 12 岁女孩遭聊天机器人辱骂**、以及一对 10 岁和 13 岁姐妹的母亲发现 **40 多段涉及暴力和控制企图**的对话。经过：**11/26 苹果将 Talkie 从全球 App Store 下架**，确认原因是应用包含性内容，未说明更多细节。当前：这是苹果第一次以「儿童安全」为由全球下架一款头部 AI 陪伴应用。

判断：**监管有两条路，一条慢一条快。**11/27 期记的是慢的那条（纽约州立法、2027-02-22 生效、每天每项罚 1.5 万美元）；这条是快的那条——**商店审核，一夜之间，全球生效，不给你申辩期**。对做 AI 陪伴/硬件的人，这条比立法更该怕：**立法给你 90 天，审核只给你一次更新**。

做法：① 如果你的产品有「角色扮演」能力，**先做一次「未成年人自述年龄」的对抗测试**，看模型会不会自己把对话推向亲密关系；② 把「儿童不可用」写成产品层的硬门槛（年龄门 + 内容分级），而不是写进用户协议。

⚠️ 下架原因以苹果对外口径为准，**具体判定条款未披露**；调查由两家媒体联合完成，**MiniMax 未公开回应全文**；「40 多段对话」为调查方统计。

源：Bureau of Investigative Journalism / ABC News 联合调查（经网易 11/26 转述）、Apple App Store 下架

## 三、潜在挣小钱的机会

**1. 前验光师一个人做的「主题→竖屏短视频」工具：$22,071 MRR、累计 $617,455，正在挂价 120 万美元出售**

路径：**给一个主题，自动写脚本、AI 配音、生成画面与字幕、剪成 30/60 秒竖屏，再按计划自动发到 TikTok 与 YouTube**。客户是想做「不露脸账号」的创作者——他们买的不是软件，是**每天不用来操作**。创始人 **Samuel Rondot**，法国人，前验光师，自学写代码，从写代码到回客服邮件都是一个人。

报价与月收入：**MRR 22,071 美元、382 个有效订阅**（折约 **$58/订阅/月**），2024 年 8 月上线至今**累计 617,455 美元**，数据接 TrustMRR（Stripe 验证）；**同时挂价 120 万美元出售**。

为什么复刻得动：他自己总结的选品法则是**「只做别人已经赚到钱的产品」**——判断标准有四条：是否有公开的 Stripe 截图、对方流量来自广告还是 SEO（两者都有说明需求强且好复制，只靠 SEO 要等很久）、技术上做不做得出来、后台好不好维护。**这套方法的价值大于产品本身**：它把「选题」从灵感问题变成了可执行的检索动作。

⚠️ 风险：① **$120 万是挂价不是成交价**，MRR 22,071 与累计 617,455 之间差 28 倍，说明它是慢热型而非爆发型；② 同类免费替代极多（MoneyPrinterTurbo 一类开源项目 14 万 stars 量级），**付费理由只能是「自动发布 + 稳定不折腾」**；③ 它的分发高度依赖平台 API 政策，**TikTok/YouTube 一次接口变更就能打断整条链**。

源：TrustMRR（11/27 快照，Stripe 验证）、腾讯新闻 11/27（哥飞访谈）

**2. $5.99/月的集换卡扫描器：55,000 用户里 3,481 个付费，6.3% 付费率**

路径：**扫卡 → 实时价格 → 组合涨跌**。用户是手里压着几百张卡和一整箱未拆封的人，**不知道值多少钱**；一次扫描给实时报价和持仓波动。定价：免费档 €0，**Premium €5.99/月、Premium+ €49.99/年、Lifetime €159.99**。

报价与月收入：**MRR $22,174，3,481 个有效订阅**；2026 年 5 月上线。

为什么值得看：**6.3% 的免费转付费率在消费级 App 里是高位**（一般 1–2%）。原因不神秘——**它的用户手里有资产**，估值的边际价值随持仓规模上升，而 €5.99 相对一张 €100 的卡是零头。这正好对上「愿意为省时间少麻烦付费」那条判据，而且场景足够窄。

⚠️ 风险：① **卡价数据源是命门**，第三方报价断供或延迟就直接失去价值；② 涉及卡面 IP 与商标，**扫描识别不等于获得展示授权**；③ 集换卡是强周期市场，**行情冷下来付费意愿会同步掉**。

源：whyitearns.com NO.015（11/27 08:00 更新，TrustMRR / 支付数据验证）

**3. 一次性 $249 买断的 Mac 小工具：两天卖了 $12,466，超过 hackathon 榜首**

路径：**Mac App，把爆款 TikTok 轮播图「重制」成你自己的版本**——它自己官网的说法是「你的 agent 在你这个赛道里找到已经爆过的内容，然后像艺术家一样偷过来」。**没有订阅**，只有终身授权：**首发前 5 个 $99，现价 $249，封顶 $299**。

报价与月收入：**11/23 起才有收入记录，11/23 $6,312、11/24 $5,302，累计 $12,466**（TrustMRR 口径）。⚠️ **一次性买断没有 MRR 可折算**，两天 $11,614 只能说明「首发势能」，不能外推月收入——这正是不写估算的原因。

为什么值得看：它证明了一件事——**在「工具类产品按订阅卖不动」的市场里，一次性买断是个被低估的定价结构**。$249 对应的是「一个能立刻用的产能工具」，而不是「一个需要持续维护的服务」，用户的决策成本低、退款争议也少。它对标的是那些靠租 TikTok API 加价转卖 token 的工具。

⚠️ 风险：① **收入榜不等于利润榜**——这场 hackathon 按利润排名（扣退款、拒付、支付费、投放），而公布的是收入；② 生命周期短，**寄生在平台的内容形态上**，TikTok 改一次轮播规则就归零；③ 「像艺术家一样偷」这个定位本身有版权灰区。

源：Indie Hackers 11/25–11/27（引 TrustMRR 日流水数据）、slideshow.sh 官网定价页

## 四、小而美产品

**Superframes（主推·给 AI 一个 brief，它按导演的方式剪完整条片子，改动可以一条条撤）**
- 是什么：**本机运行的 AI 视频剪辑器**，前身叫 CapCutGPT。三种模式：**Chat** 单次改、**Editor** 用一段 brief 剪整条、**Clipper** 把长视频拆成一板带字幕的竖屏短片。浏览器 + Mac + Windows，**免费开始、不用账号**。编辑与导出全部在本机完成（FFmpeg 编译成 WebAssembly，浏览器里解码与渲染），**视频文件不上传**；计划编辑只看 brief 文本、片段基本信息、本地转写与音量、可选的低分辨率帧
- 差异化：**它不是「一句话出片」，是「可撤销的剪辑」**。每一步改动都列成条目，能撤单条也能全撤；**Studio** 有多轨时间线，删转写里的句子会真的把对应画面剪掉。40+ 操作（裁切、字幕、竖屏重构、调色、降噪、人脸模糊、0.25–4x 变速、防抖、水印、压缩、合并、转格式），**19 种语言的逐词字幕在本机跑 Whisper**，竖屏重构带人脸追踪。另有 **MCP server** 可接 agent
- 用在哪：**短剧/漫剧的「精修前的第一刀」**——不是用来做剧集正片，是用来把 30 分钟的口播素材、拍摄花絮、直播回放拆成 10 条带字幕的竖屏切片，给投放和账号矩阵用。对你有两处直接价值：**① 素材不出本机**，未上线的剧本画面和演员素材不必上传；**② 改动可撤销**，agent 剪错了不用重跑，撤那一条就行。桌面版的「整文件夹批处理」适合一次给 20 条素材套同一套处理
- ⚠️ 风险：**它面向的是口播/播客/课程这类「有转写就能剪」的内容，不是叙事剪辑**——没有多机位对齐、没有对白轨与音乐轨的自动平衡，剧集正片仍然要回剪映/PR；**生成能力是唯一离开本机的部分**（发出 prompt、要念的文字、你选的那一帧），credits 单价：Fast 图 10、Fast 视频 13/秒、配音 9/千字、音乐 20/轨，**失败或取消的生成扣 0**；浏览器版 Clipper 输入上限 **45 分钟 / 2GB**（桌面版无此限），4K 大文件吃内存，速度跟着你的机器走；定价 **7 天通行证 $4.99 一次性 / 月付 $9.99（1,000 credits）/ 年付 $59.88 / 终身 $79（2,000 credits）**，免费档首次导出无水印
- 源：superframes.io 官网与定价页、Product Hunt 11/27（#20，74 票）、ChatGate / PowerfulAI 工具页 11/27

**Hub by Icons8（主推·把 100 个 Claude Code / Codex 会话管成 5 个：你只写目标，只回答需要你决策的问题）**
- 是什么：**开源自托管的智能体调度器**，本身不是模型、没有运行时——它跑的每一个会话都是真实的 Claude Code 或 Codex 进程。**11/19 在 GitHub 公开，11/24–11/26 上线 Product Hunt**（两处记录日期不一致，均记 **422 票、当日第 1**）。**Apache-2.0、无付费档、无托管版**，用你自己的 Claude/ChatGPT 订阅，一行命令装在笔记本或服务器上（服务器上关掉笔记本它继续跑），macOS/Linux/Windows 都可
- 差异化：**分工是「协调者 + 常驻 agent + 短命执行者」**——你在一句话里写目标，协调者拆解并拉起会话；常驻 agent 各管一块（带自己的工具与笔记）；短命执行者**在自己的 git worktree 里干一件活**，所以并行不会抢同一个文件。几个少见的细节：忙的会话**消息排队、不丢**（紧急消息能插进当前轮次）、崩溃后**带着对话恢复**、会话之间**能读彼此的步骤与结果**、结果要附证据（截图/视频/前后对比）且**先由另一个模型的 critic 试着反驳**、下有事件日志当唯一真相源、有 watchdog 盯死循环与重复报错。作者自报：**约 1.2 万个测试、每次发版都在 Windows 上跑过**，8 天内 5 个 release
- 用在哪：**你现在这种「同时开好几个 agent 跑不同活」的状态**——一个在改小程序云函数、一个在跑数据核对、一个在写文档，最烦的不是等，是**不知道哪个卡住了、哪个在等你**。它的 Now 标签页只显示「等你的事」。真实使用证据也在这：作者用它重写遗留后端，**9/20 以来合并 546 个 MR**；阿根廷 Pinamar 的公立医院与 6 个卫生中心用它搭了预约系统，**86 名医生、10 月底起接真实病人**
- ⚠️ 风险：**官方把「agents 在没有权限确认的情况下运行」加粗写在首页**，让你「像对待本机终端一样对待它，先读 SECURITY.md」——这条比任何功能都重要，**它把 Claude Code 的刹车搬到了调度层，单个会话里是松的**；明确标注实验性；**公司作品（Icons8 出品），不是独立开发者项目**，好处是有维护，坏处是路线跟着它的商业需求走；多会话并行会把你的订阅额度吃掉得比你以为的快（内置 Usage 页能看限额与预测）
- 源：GitHub `icons8/hub`、Product Hunt 11/24–26（422 票 / 167 评论 / 当日第 1）、usehub.dev、AI Core Updates 11/27

**QA.tech MCP（备选·给 IDE 里的编程 agent 配一个「外部 QA」，每次改完都替你在应用上跑一遍）**
- 是什么：把端到端测试作为 **MCP 服务**接进编程 agent。**每次改动后，它在你的应用上自己探索、写测试、跑测试，找出 agent 漏掉的 bug 与边界情况，agent 读到结果再修**。任何 MCP 客户端都能接
- 差异化：**它补的是 agent 闭环里唯一空着的那一环——验收。**Claude Code / Codex 能写能改能自测，但「我改的东西在真实页面上点起来对不对」一直靠人。把它接进 MCP 之后，agent 的循环从「改完就说完成」变成「改完→跑→看结果→再改」
- 用在哪：**小程序/Web 这类有明确点击路径的产物**。你让 agent 改一个下单流程或一页报表，最容易错的是「功能对了但入口点不到」「状态没刷新」——这类 bug 单测测不出来，人工点一遍又太慢
- ⚠️ 风险：**本条信息最薄**——仅来自 Product Hunt 11/27 榜单（#2，183 票）与第三方日报转述，**我刊未取得官方文档、定价页与权限说明**；「在你应用上跑测试」意味着**它需要能访问你的测试环境与测试账号**，权限边界必须先问清；对强登录态、验证码、支付链路的覆盖能力未知
- 源：Product Hunt 11/27（#2，183 票）、数字航海家《11月27日海外新品观察》
