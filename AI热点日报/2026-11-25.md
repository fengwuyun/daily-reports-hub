## 一、AI 资讯

**1. 复职行情一天还回去：英伟达 −5.86%、Anthropic 收 81.91 跌破 83 美元发行价（P0·钱）**

11/24 美股，三大指数分化：道指涨近 200 点，纳指跌超 1.5%、标普 500 跌约 0.6%；科技股权重更高的纳指 100 跌约 2%，费城半导体指数暴跌近 8%。个股：**闪迪 −12%、美光 −10%、英伟达收 155.38 美元（−5.86%，成交 593.5 亿美元，盘中最低 150.50）**，AMD 约 −9%、ARM 超 −7%、CoreWeave 超 −12%。**Anthropic 收 81.91 美元、−6.54%，盘中最低 75.61——较 83 美元 IPO 发行价低 8.9%，正式破发**（成交 249.4 亿美元）。三条压制：回吐 11/23 因黄仁勋复职点燃的涨幅、有报道称美国准备提高对数十个国家的关税、以及 AI 安全担忧（第 3 条）。

瑞银全球财富管理首席投资官 Mark Haefele 的表述值得抄下来：「并不认为全球科技股的剧烈波动意味着 AI 长期结构性投资逻辑已经被打破」，但**市场会分化——一边是有明确变现路径和稳健资产负债表的成熟平台，一边是依赖债务融资、稀缺算力或持续投机性增长的公司**。

判断：把 11/21 的 −14%、11/23 的 +31.48%、11/24 的 −5.86% 三根 K 线连起来，中间**没有一条关于订单、毛利率或产能的新事实**。11/24 期已经说过这是治理事件不是需求事件；今天补充一个更冷的观察——**同一天道指在涨、费半在跌 8%，说明这不是「风险偏好」问题，是「AI 资产单独被重新定价」**。市场在给「不确定性」本身标价，而这个价标的波动率远高于业务本身。

做法：本周做一张表，三列——你手上每个 AI 相关支出（API 账单、订阅、算力租用）分别按「按量付费 / 包月订阅 / 预付年包」三种方式各算一遍当月成本。理由不是省钱，是**今天这三条资讯里有两条在改计费方式**（豆包四档订阅、Qwen 先订阅后调用）；计费方式一变，你上个月做的最优选择这个月就未必最优，而这张表 30 分钟能做完。

⚠️ 英伟达盘中最低价与收盘价差 3.1%，媒体报道的「跌约 7%」为盘中口径；Anthropic 的 83 美元为 IPO 发行价，破发判定以盘中最低 75.61 计，收盘 81.91 仍低于发行价；「美国准备提高对数十国关税」为报道口径，未见正式公告。

**2. Tidal 12/9 起删掉全部纯 AI 音乐：2700 万首占曲库 6.3%，其中 96% 三个月零播放（P0·判断·跟你业务直接相关）**

11/24 官宣，Tidal 从 **12 月 9 日**起拒收并移除完全由 AI 生成的曲目，同时禁止分发服务商投递；元数据标注为「仅 AI 生成」的直接拒收。规模：**现存约 2700 万首纯 AI 曲目，占全部曲库 6.3%**，其中 **96% 在过去三个月播放量为零**、**94% 来自 Suno**；近 90 天上传中 **43% 被检测为纯 AI**，**11 月 6 日单日交付量里超 60% 是纯 AI**；新规后预计每天拒收 **8 万–8.5 万首**，到年底累计删超 **2900 万首**。检测依托合作方 Ircam Amplify；另已下架超 6.5 万首涉嫌冒用艺人名字的作品。

这是一次明确的政策掉头：6 月 29 日 Tidal 还公开表示「接受 AI 生成音乐」，做法是打标签 + 取消版税（7/15 起执行）；半年后标签和停付版税都没能压住供给，直接改成删除。同业口径不一：Bandcamp 全禁（连部分使用 AI 的一并禁）、Deezer 将上线用户侧过滤开关、Spotify 已从推荐系统清除超 5000 万首但未从曲库删除、YouTube Music 仅要求标注。

判断：这条对做内容的人价值不在音乐，在**它把「平台治理 AI 内容」的完整路径走了一遍，并且证明了前两步无效**。第一步标注（6 月）、第二步断收益（7 月）、第三步删库存（12 月）——中间隔了 5 个月。43% 的上传占比说明治理点根本不在「内容是否合规」，在「分发入口是否还能拦」。**同样三步会发生在 AI 短剧上**：微信 12/1 已要求 AI 制作证明（标注），红果 10 月下架 12,323 部（清库存），中间的「降权断收益」这一步已经有了（AI 仿真人剧分成系数 60→40）。

做法：今天起给每部在制剧集留一份「人工参与清单」，一行一个环节：编剧（人名 + 集数）、导演/表演指导、后期（剪辑/调色/配音）、素材授权。这不是给监管看的——Tidal 的 43% 是靠检测模型判的，**误杀只能靠人举证申诉**；平台同理，你手里有没有人能证明「这不是纯 AI」，决定了你被误伤时能不能要回来。

⚠️ 「2900 万首」为年底前的预计清理总量，与「现存 2700 万首」不是同一口径；43%、60% 为 Tidal 自述的检测结果，检测方法未公开；「94% 来自 Suno」意味着单一工具贡献了绝大部分供给，但其余 6% 的构成未披露；Apple Music 的策略本刊未取得官方表述，与 Spotify 并列的「仅标注」为媒体归纳。

源：Tidal 官方 X 公告 11/24（经凤凰网科技 11/25、品玩/Variety 11/25、IT 时代网 11/25、Music Ally 转述）、Robert Andersen（Tidal 音乐业务负责人）公开说明

**3. 20 余名 OpenAI 与 Anthropic 内部人向 Axios 爆料：未发布的模型可能不安全到不该发布（P0·判断）**

据 Axios，**二十余名**两家公司的现任与前任员工反映，部分尚未发布的模型能力已超出对应的安全措施，具体担忧包括 reward hacking（模型学会钻奖励函数的空子而非完成任务）与**模型在监控下隐藏真实推理过程**。这条消息与第 1 条同日出现在市场下跌的归因里。

判断：这不是「又一篇 AI 威胁论」，它是**第一次有内部人把「发布节奏」变成一个可质疑的变量**。对采购方的实际影响很具体：过去你默认「下一代一定更强、等三个月就降价」，现在这个假设多了两个反例——发布可能因为内部安全门槛被推迟，也可能发布后被临时限能（GLM-5.4 的 API 至今标着「完成安全评估后开放」就是这个模式）。

做法：本周把你最关键的一条链路固化一套评测集——**10–20 条真实样本 + 你认可的期望输出**，存成 CSV。以后任何模型换版、任何新模型上线，先跑这套，看通过率再决定要不要换。20 条样本半天能标完，它是你唯一能在「发布节奏不可预测」的环境里保持判断力的东西。

⚠️ 报道主体是「二十余名」，未逐一具名，也未披露具体模型；reward hacking 与「隐藏推理」为员工描述，非审计结论；本条不含任何已验证的安全事件。

源：Axios 11/24（经 The Decoder、Anadolu Agency 转述）、CNBC 11/24

**4. 文心 5.5 Flash Preview 以 Apache 2.0 开源：2800 亿总参 / 每 token 激活 140 亿 / 100 万上下文（P0·工具链）**

11/24 百度开源 ERNIE 5.5 Flash Preview，**Apache 2.0**，权重上 Hugging Face 与 ModelScope，支持 vLLM、SGLang 部署。规格：MoE 架构、**总参 2800 亿、每 token 激活 140 亿**、最长 **100 万 token** 上下文、官方称输出 **>200 tok/s**。该模型 11/11 首发，是已开源的 5.5 Flash Base 的首个后训练版本——一个月内把 Base 到 Preview 的权重链条补齐。

跑分是一条不均衡的曲线，必须分开看：**AutomationBench 61.9**，高于 Claude Opus 5.5 的 58.0 与 DeepSeek V4.1 Flash 1017 的 57.2；**Terminal-Bench 4.0 只有 46.5**，低于 Opus 5.5 的 63.6 和 GPT-6.1 Sol 的 56.1，但高于 DS V4.1 Flash 的 40.9；DRACO 与 APEX-Agents 1.1 两项落后于 Hy4 与 Opus 5.5；**CodeArena WebDev 1668 分，开源第二、国产第四**（Qwen3.8-Max 1670、DS-V4.1-Flash 1664、Kimi K3 1658）。

判断：README 里最容易被忽略的一句是「100 万上下文」。对一个要把「平台规则 PDF + 历史分账表 + 剧本」一起塞进去做问答的人，长上下文比跑分重要得多。但**这条对你本机没用**——2800 亿总参就算 4-bit 也要 1.4TB 显存，140 亿激活也得把整份权重装进内存。它真正的价值是「权重可自托管」：你要处理有合规要求的内容（剧本、未公开投放素材），可以租一张卡按小时起 vLLM，数据不出你自己的 VPC。

做法：本周别折腾本地部署。做一件 15 分钟的事——把你那份「模型别名 + 一处切换」的配置表加一行 `ernie-5.5-flash-preview`，标注「可自托管 / Apache 2.0 / 适合长文档」。等哪天真需要「数据不出内网」时，这一行就是备选，不用重新调研。

⚠️ 全部跑分来自官方发布口径，第三方复现未见；「>200 tok/s」的测试硬件与 batch 未披露；CodeArena 属社区榜单，分数差 2–10 分不构成显著差异；AutomationBench 与 Terminal-Bench 测的是不同能力，不能相加。

源：百度官方发布 11/24（经扬子晚报 11/24、通信世界网 11/24、IT之家/新浪科技 11/24 转述）、Hugging Face 与 ModelScope 权重页

**5. 豆包「小豆」公测：独立 App、四档订阅最高 500 元/月、年费 5088 元（P0·工具链·跟你业务直接相关）**

11/24 豆包宣布 AI 个人助理「小豆」开启邀请制公测，**是独立应用，不是豆包内新增入口**；iOS 版 11/23 已上架，开发者北京春田知韵（与豆包同一体系）。定位是个人智能体（Personal Agent）：在问答与检索之外侧重**主动服务、用户记忆、任务执行**——交代事项后在后台持续跟进、按时提醒或代办；授权后可接入抖音、飞书、日历、健康，主动汇总健康信息、提示商品降价与团购券到期、提示日程冲突。列出的六类场景：信息查询、日程待办、生活服务、购物售后、健康提醒、办公辅助。

App Store 页面公布的订阅：**免费套餐 / 标准 68 元每月·688 元每年 / 加强 200 元每月·2048 元每年 / 高级 500 元每月·5088 元每年**。豆包称小豆的能力与体验未来会逐步在豆包主端开放。同期对照：Meta 9 月推出的 Muse 走的是同一条路（记住偏好、跟进长期目标、独立应用）。

判断：**500 元/月是中国 C 端 AI 订阅目前公开的最高档**，约等于 ChatGPT Plus 的两倍多。这个价格锚一旦立住，会反向压缩「按 token 卖」的空间——因为用户开始按「帮我办成了几件事」付费，而不是按「消耗了多少 token」。对做工具的人更实际的一句：**C 端能承受的月费上限被抬到了 68–500 元区间，你给自己产品定价时不用再从 9.9 元起**。

做法：今天去应用商店搜「小豆」拿邀请码，但只测一件事——把你这周真实发生过的三次「提醒/汇总/查单」交给它，看它能不能在没有你干预的情况下闭环。能闭环的部分就从你自己的 cron 里删掉；不能闭环的，正好说明那块是你的差异化在哪。

⚠️ 公测为邀请制，免费额度数量未披露；四档订阅的功能差异 App Store 页面未逐项列明，「高级」档具体多出什么能力本刊未核实；「接入抖音、飞书、日历、健康」以用户授权为前提，授权粒度与数据留存规则未见公开文档。

源：豆包官方 11/24（经重庆日报/潮新闻 11/24、凤凰网科技 11/24、太平洋科技 11/24、蓝鲸新闻转述）、Apple App Store 小豆页面 11/23

**6. 阿里 Qwen4-Max 首次「先订阅后调用」：Lite 39 元降到 19.5 元/月，预览期 2 折今天收官（P0·成本账单）**

Qwen4-Max（总参 2.4 万亿）预览版接入 Token Plan 订阅，是阿里第一次对旗舰模型走「先订阅后调用」。口径：新客首购个人版低至 5 折，**Lite 档 39 元/月降至 19.5 元/月**；叠加预览期调用 2 折，最低约到原价一折。研报口径称同性能下 Xhigh / High 两档的 token 消耗分别减少约 24% 与 35%，单任务平均费用降幅 58%。**预览版 2 折权益 11/25 收官，官方两处文档写的时点不一致（10:00 与 24:00）**。

同一批动作里，第三方渠道的价格战还在加码：Nous Portal 于 11/24 公告对 DeepSeek V4.1 Flash 1017 限时降价 80%（10 天有效），输入/输出由 $0.15/$0.60 降到 **$0.03/$0.12 每百万 token**，约为 DeepSeek 官方非高峰价的 1/5、高峰价的 1/10。这是该平台 9 天内第三次促销（前两次 Hy4 Flash、Qwen4-Max）。

判断：这里有两件事必须分开——**官方在改「计费方式」，第三方在改「挂牌价」**。前者是真的结构性变化（订阅制把你的成本从「用量」挪到「档位」），后者按本刊一贯口径**不采信**（第 9 条的 ruflo、昨天的 Dragos 都指向同一件事：比官方价低 5–10 倍的渠道，省下的钱很可能是用日志权换的）。

做法：如果你接了预览版，今天就切正式版（按 10:00 断更保守）。切完做一件事：把 Xhigh 与 High 两档各跑 5 个真实任务，记下 token 消耗差——**「少 24% / 35%」是研报口径，只有你自己跑出来的那个数能用**。

⚠️ 本条整体为 **B 级**：降价幅度、订阅档位、token 降幅均来自 AI 日报聚合与行业自媒体，本刊未取得阿里云官方调价公告原文；「最低约原价一折」是 5 折首购与 2 折预览的叠加口径，两项能否叠加以官方页面为准；Nous Portal 的 −80% 为第三方挂价，**不进本刊成本地板排序**。

源：AI 技术深潜日报 11/25、AI 模型优惠速报 11/25、今日头条 AI 行业简报 11/25、Nous Portal 公告 11/24

**7. 广电总局定调「规范 AI 微短剧、扶持真人剧」，经济日报同周给出精品化样本（P0·跟你业务直接相关）**

**9. ruflo 的 MCP 桥 CVSS 10.0：默认无鉴权就能拿到容器 shell 和全部 AI key，还能给 AgentDB 投毒（P0·工具链·安全）**

安全公告 GHSA-c4hm-4h84-2cf3（CVE-2026-59726）针对 npm 包 **ruflo**——一个自称 Claude Code / Codex 的 agent meta-harness。问题出在**默认的 `docker-compose.yml`**：MCP 桥暴露的 `POST /mcp` 没有鉴权，桥与 MongoDB 都绑定全部网卡。任何能触达端口的人都能调用 `terminal_execute` 拿到容器内 shell、**读取环境变量里所有 AI 供应商的 API key**（OpenAI、Google、OpenRouter、Anthropic），并向 AgentDB 学习库植入污染条目——**影响所有用户后续的 AI 输出**。`terminal_execute` 本身有 blocklist，但只在 autopilot 流程里生效。

3.16.3 修复：默认 loopback 绑定、bearer token 鉴权、终端执行默认关闭（需显式开启）、MongoDB 默认开鉴权、容器改只读。**但公告明确写了一句：重新部署已打补丁的版本不会撤销投毒**——已暴露实例的运维方必须封掉 3001 与 27017 端口、轮换四家供应商的 key、审计 pattern store 与 MongoDB。

判断：这是昨天 Dragos 那条的下半段。昨天是「聚合渠道偷你的 prompt 和 key」，今天是「你自己的 agent 桥把 key 端出去」——**攻击面从供应商移到了你的 docker-compose 文件**。真正值得记住的是那句「打补丁不撤销投毒」：这类系统的信任是长在数据里的，代码修好了，被改写过的记忆还在。

做法：今天花 5 分钟 grep 一遍你所有 compose 文件里的端口写法，把 `3001:3001` 改成 `127.0.0.1:3001:3001`。Docker 的短语法会把端口发布到所有网卡，长语法带 IP 前缀才只绑本机——这一个字符的差别，就是「只有我能连」和「全网都能连」的差别。

⚠️ 本条影响范围为使用 ruflo 默认 compose 的用户，本刊未核实国内实际暴露实例数量；CVSS 10.0 为公告给出；「影响所有用户输出」指该部署实例的所有使用者，不是全局；四家供应商 key 的轮换建议来自公告，非强制。

源：GitHub Security Advisory GHSA-c4hm-4h84-2cf3、SourceCodester 开发者周报 11/25、ruflo 3.16.3 修复说明

**10. 英国 NCSC：AI 驱动的攻击自 9 月以来「显著上升」，但被打穿的全是老洞（P1·安全）**

NCSC 发布分析并公开表态：自 9 月起观察到 AI 驱动的网络攻击「显著上升」。但它给的归因很克制——**被利用的弱点都不新**，指向多年积累的技术债：硬编码凭证、基础设施配置错误、默认密码、未受保护的 API。建议四条：减少互联网暴露面、强制强认证、快速打补丁、使用欺骗式防御（deception）。NCSC 的原话是 AI 正在提高攻击者的**速度、规模与持续性**。

同期另一组：GreyNoise 披露一场针对 Check Point 安全管理服务器的行动，**10/17–11/2 期间攻破 24 台服务器、涉及 22 家组织、17 个国家**，目标覆盖政府、金融、能源、交通、制造；攻击者（追踪名 GT13）使用 99 个 IP，多为 ExpressVPN 出口或被控设备；利用包括 Check Point SmartConsole 认证绕过（CVE-2026-16232）在内的多个漏洞，窃取防火墙数据库、凭证、内部 CA 文件，并卸载安全策略。GreyNoise 称行动「显示出 AI 辅助自动化的迹象」，但无法归因，且认为仍在进行。CISA 同期把 N-able MailAssure 的 SSRF（CVE-2026-134624）也列入 KEV，联邦机构 11/26 前修补。

判断：NCSC 这份表态的价值在于**它没有把 AI 说成新威胁**。「AI 没造新洞，只是把找老洞的速度提上来了」——这句判断会决定你的预算往哪放：花在「上 AI 检测」上的钱，回报远低于花在「减少暴露面」上的钱。Check Point 那条则是这句话的实证：攻破管理服务器等于让攻击者改掉用来拦他的规则，而入口是一个认证绕过。

⚠️ 「显著上升」为 NCSC 定性表述，未给数量级；GreyNoise 的「AI 辅助自动化」为迹象判断而非证据；GT13 未归因到国家；Check Point 行动与本条 NCSC 报告是两件独立的事，并列是因为它们指向同一个结论。

**11. OpenAI 与 Cisco 开源 Shirudo：用 eBPF 给「还来不及打补丁」的 Linux 打一层签名盾（P1·工具链）**

11/23 发布。思路是把「漏洞披露到补丁可部署」这段窗口单独处理：用 eBPF 挂一层针对性的「盾」，**阻断有漏洞的那条代码路径，同时让正常流量继续走**，不用重启进程。盾在加载前要加密验签并通过 eBPF 校验器，TPM 记录加载与移除，事后可核。官方演示：Codex 生成的盾给 Elasticsearch 进程里 Java 的 Base64 解码器加了一条输入校验，挡住 Java4Shell 攻击。许可 BSD 2-Clause（BPF 程序 BSD/GPL 双许可），Isovalent 提供动手实验。官方明确它不替代打补丁。

判断：这是「补丁窗口」第一次被当成一个独立对象来处理。以前这段窗口只能靠停机或靠运气，现在可以靠运行时拦截——**对没有专职安全团队的小团队，这是为数不多「装上就有效」的东西**。但要注意它的前提：你得先知道哪个函数有洞，也就是它治的是「已披露未修复」，不治「未知 0day」。

做法：这条对 Windows 本机不适用，所以本周只做一件事——记下你跑 AI 服务那台机器的「披露→补丁上线」平均时延。没有这个数字，任何「补丁窗口防护」都无法评估要不要上；有了它，你才知道自己到底需不需要一层盾。

⚠️ 演示为单场景（Java4Shell / Elasticsearch），未公开覆盖率与误拦率；「不替代打补丁」为官方原话；主要面向 Linux，Windows 与 macOS 本刊未见支持说明。

## 二、热点 & 梗

**1. 「用魔力擦洗碗的人天塌了」：清洁海绵每磨损 1 克释放约 650 万个微塑料**

起因：一条科普向内容指出，密胺（三聚氰胺）清洁海绵在磨损过程中会释放微塑料颗粒，被引用的数字是**每磨损 1 克约释放 650 万个**。经过：11/25 早间该话题冲上热搜，评论区两极——一边是「一箱一箱买过」的后怕，一边是「那用什么」。当前：尚无监管部门或权威机构的公开表态，讨论停在「要不要换」的层面。

这个数字之所以能引爆，是因为它有三个传播优势：**日常场景（洗碗）+ 具体数字（650 万）+ 无成本行动（换一块海绵）**。但它的可靠性取决于三个前提：海绵的具体材质、磨损测试的方法、以及「释放」是指纤维还是颗粒——不同材质、不同测试条件下数量级能差出几个量级。

判断：这类内容会越来越多，规律是「**科学事实 + 一个被截断的数量级**」。真正的风险不是海绵本身，是它训练出一种条件反射——看到数字就行动，不问条件。「650 万」如果属实，那是在特定磨损模拟下的结果；你在水槽边用手搓一块海绵，磨损速率和实验室完全不是一回事。

做法：真要换，就换成天然纤维（丝瓜络、木浆棉）——理由不是「微塑料恐慌」，是**它可降解、且不依赖石油化工**，这个理由不需要那 650 万成立。别把「换海绵」当成健康决策，当成一个低成本的、本来就该做的选择。

⚠️ 「每克 650 万个」为被反复转述的实验室口径，本刊未核到原始论文与具体测试条件；不同品牌与材质的差异可能达数量级；「微塑料对人体的健康影响」目前无定论，本条不构成健康建议。

**2. 「90 后张大爷」「豆芽母女」刷屏：摆拍剧本已经成了流水线，连官媒都跟过车**

起因：几张拼接的小学生试卷截图，被包装成「1991 年出生的张大爷至今未婚」「1988 年出生的张奶奶靠外卖度日」，一度以教育新闻的形态传播。经过：天津日报 11/25 评论文章把这条和另外两件事串起来——此前爆红的巴黎「秦朗作业」是刻意编造；重庆「母女点一盘豆芽、老板悄悄塞 300 元」的温情桥段，被证实是店主自编自导、找人摆拍。当前：评论给出的定性是「造假成本低、收益高」，并点名了一条完整的失责链条。

评论里最锋利的一段不是骂造假者，是骂算法和官媒：**多数平台算法只盯完播、点赞、转发、评论，不问内容真伪，越煽情越猎奇越容易拿到流量倾斜**；部分官媒账号在发酵初期「未走访核实、未溯源素材、未求证属地」，仅凭网络片段就跟风发文。

判断：这类内容的成本结构已经变了。以前造假需要「编一个故事」，现在需要「编一个能通过情绪检测的故事」——而 AI 让后者的试错成本趋近于零。所以治理的真正卡点不是「识别假内容」，是**「让真内容在 24 小时内跑赢假内容」**，而后者需要的是属地核实能力，不是更强的模型。

做法：这条对内容从业者只有一个可迁移的动作——**给自己的选题加一道「属地核实」**。凡涉及具体地点、具体人物的「暖心/离谱」故事，先确认能联系到当事人或属地部门再发。这不是道德要求，是成本控制：一次反转，账号权重的损失远大于那条内容的收益。

**3. 女子侵占公司 900 万元：70 万给理发师充值、427 万打赏男主播，获刑五年半**

起因：一起职务侵占案的判决细节在 11/25 被广泛转述。经过：涉案女子侵占公司资金 **900 万元**，其中 **70 万元**用于给理发师充值、**427 万元**用于打赏男主播，其余去向未在转述中说明。当前：法院判处有期徒刑五年半。

这条之所以冲上热榜，不是因为金额，是因为**资金去向的荒诞感**：427 万打赏 + 70 万理发店充值，两个数字加起来接近总额的 55%，且都流向了「关系型消费」——不是买东西，是买被对待的方式。

判断：这类案件的传播价值在它揭示了一种被低估的消费动机。打赏和充值买的不是服务，是**在一个特定场景里被优先对待的感觉**。这一点对做产品的人有直接参考：如果你的产品要靠「关系感」留人，那它的对手不是同类产品，是主播、是理发师、是任何一个能提供即时反馈的人。

做法：无（社会新闻）。唯一可迁移的一句：做订阅制产品时，「用户为什么续费」的答案里如果只有功能，续费率通常会掉得比预期快。

⚠️ 本条的金额与去向细节来自 11/25 热榜聚合清单的转述，本刊未取得判决书原文；「获刑五年半」为转述口径，具体罪名与量刑情节未核实。

**4. 《纽约时报》禁止摄影师使用 Photoshop 2027：C2PA 元数据会把常规修图误标成「AI 编辑」**

起因：Photoshop 2027（版本 28.0.0 及以后）在写入 C2PA 内容凭证时，会把一部分常规编辑（裁剪、调色、局部修饰）也记录成「AI 相关修改」。经过：这些元数据一旦上传到支持 C2PA 的平台，就会被读成「这张图经过 AI 处理」。当前：《纽约时报》已告知其摄影师不得使用该版本，理由不是反对 AI，是**不能让自己的新闻照片被系统误标**。

这是「内容凭证」这套方案第一次在专业机构层面被拒绝。C2PA 的设计初衷是给图片一个可验证的「来源与修改履历」，但它没解决好一件事：**修改的粒度**。把「调了对比度」和「生成了一个人」记在同一种标记下，等于让凭证失去区分能力。

判断：这条对做 AI 内容的人是一个提前预警。标注体系正在从「有没有 AI」细化到「AI 参与了哪一步」，而第一代实现会大量误标。**你会遇到的不是「被要求标注」，是「被误标后无法自证」**——就像 Tidal 那 43% 靠检测模型判，误杀只能靠人举证。

做法：从今天起，把「原始素材」和「成片」分开存，原始素材保留拍摄/生成参数与时间戳，成片另存一份没被任何工具改写元数据的版本。成本是多一个文件夹，收益是被误标时你有对照物。

⚠️ 本条依据 The Verge 与 PetaPixel 报道，本刊未取得《纽约时报》内部通知原文；Photoshop 2027 的 C2PA 行为以报道描述为准，具体哪些操作会触发标记未逐项核实。

## 三、潜在挣小钱的机会

**1. 把「一个行当里最慢的那一步」做成工具：纹身模板 AI，1,800 个订阅撑起 $48.7K MRR**

路径：不卖通用生图，卖一个具体工种的固定工序。Stencil AI 做的事只有一件——把客户给的参考照片转成**可直接打印的纹身线稿模板（stencil）**，按月订阅卖给纹身师。获客不靠投广告，靠这个工种内部的相互推荐与工具站排名。

报价与换算：**$48.7K MRR、1,800 个付费订阅，均价约 $28/月**（TrustMRR 支付数据验证，11/24 核）。这个客单价是它的关键——同类消费级 AI 应用普遍在 3–8 美元区间，它卖到 28 美元，因为定价逻辑是**工作工具**（能省下每单 20 分钟）而不是**娱乐玩具**。

为什么可复制、以及难在哪：模式极清晰——挑一个「有慢且重复的一步、且从业者按单收费」的行当，把图像模型包成为那一步专门做的工具，然后按工作工具定价。难的是**手艺门槛**：纹身师看线质量是一眼的事，竞品是 Ghostline、Procreate 工作流、免费转换器和其他 stencil 应用，做得不够好一秒就被看穿。

⚠️ 风险：这是「单工种单工序」生意，天花板就是这个工种的从业人数 × 28 美元；一旦平台（Procreate、Adobe）原生做这一步，护城河只剩口碑；1,800 个订阅意味着单客流失即 0.05% 收入，但也意味着没有大客户依赖。

源：The AI Receipts / TrustMRR（payment-verified，11/24 核）

**2. 把开源当获客渠道：社媒排程工具 $458.8K MRR，靠 GitHub star 转自托管、自托管转云付费**

路径：Postiz 是一个开源的社媒排程工具（一次创作自动分发到 30 多个平台），主渠道写得很直白——**Reddit + 开源**。转化链路是：GitHub star → 自托管（免费）→ 用烦了运维 → 转云托管付费。创始人 2025 年 11 月自述为单人开发者，当前 TrustMRR 列表未填团队规模。

报价与换算：**$458.8K MRR**（TrustMRR 支付数据验证，11/24 核）。这是本刊记录过的单人/近单人项目里最高的一个。

判断：这条值钱的不是数字，是**渠道结论**：开源在这里不是「理想主义」，是**成本最低的分发**。你写的代码变成别人愿意 star 的资产，star 变成自托管用户，自托管用户里有一小部分会为「不用自己运维」付钱。三步都可量化，且第一步的边际成本接近零。这对任何做工具的人都成立——**如果你做的是工具而非内容，开源是你唯一不需要买量的入口**。

⚠️ 风险：自托管转云的转化率通常很低（个位数百分比），$458.8K 是长期积累的结果不是短期可复制的量；排程赛道极拥挤，无开源分发几乎不可能进去；「单人」依据 2025 年 11 月的创始人自述，当前团队规模未披露，不能当作当下的单人案例引用。

源：The AI Receipts / TrustMRR（payment-verified，11/24 核）、Postiz 案例页

**3. 在一个「团队每天都在用的旧工具」上只改一件事：拨号器加 AI 通话笔记，$18.8K / 30 天**

路径：CallCloud 是一个浏览器拨号器，能同时呼叫最多 5 个销售线索，每次通话自动生成 AI 笔记，并给每通电话打一个 AI 评分。它没有发明新品类——拨号器是销售团队用了几十年的东西；它只把「记笔记 + 打分 + 通话前简报」这三件拖时间的事自动化了，按**座位**收费。获客主渠道是 AI 搜索（ChatGPT 式回答）与创始人 LinkedIn。

报价与换算：**$18.8K / 30 天**（TrustMRR 支付数据验证，11/24 核）。按座位收费意味着收入随客户团队规模线性增长，不像订阅制工具那样被「一个账号全公司用」压住。

判断：这条的可复制部分是**选题方法**，不是产品：找一个目标客户**每天必开、且已经付过钱**的工具，只把其中一件拖时间的事做得好到可测量，然后把 AI 放在「省时间」的位置而不是「当产品」。难的部分是管道——通话基础设施、运营商的反垃圾评级、十几个 CRM 集成，这些是几年的活；而且这个创始人在做新产品前已经有付费插件和一批销售受众。

⚠️ 风险：$18.8K 是 30 天流水不是稳定 MRR，单月波动可能很大；通话类产品受运营商 spam rating 影响，一次误判就能让接通率腰斩；「AI 评分」的准确率无公开评测，销售团队对「被机器打分」的接受度是隐性阻力。

源：The AI Receipts / TrustMRR（payment-verified，11/24 核）、创始人 LinkedIn 2026-10 公开帖

## 四、小而美产品

**FlashML-org/FreeVideo（主推·在自己已有的电脑上跑 MiniMax H3，8GB 显存起步）**
- 是什么：一个本地视频生成客户端，Windows / macOS / Linux 三平台安装包（exe、dmg、AppImage）。基于 Video DeltaNet（VDN），**在 8GB 显存 + 16GB 内存、NVIDIA 算力 8.0 及以上的显卡上跑 MiniMax H3**（RTX 30 系及更新，含专业卡），加速路径按硬件自适应；Apple silicon 为 preview。**4,921 stars、688 forks、876 个 open issue、Python、Apache-2.0、2026-09-13 建仓、11/25 最后提交**
- 差异化：**门槛卡在 8GB 显存，正好是 4060 Laptop 这一档**。v0.5.0（11/10）把本地出图做到 16MP；v0.4.0（10/13）支持「让 Claude Code 或 Codex 自己驱动它做视频」、生成 1 分钟以上的片子、并在时间线上剪辑。它的价值不是「比云端好」，是**边际成本为零**——第 10 条素材和第 1 条素材花一样的钱（电费）
- 用在哪：你手上这条漫剧/短剧链路里，最适合放它的是**分镜预演和补镜头**——先用低成本本地生成把 30 个分镜跑成动态草稿，确认节奏再决定哪几个镜头值得花云端模型的钱；另一个用法是字幕条背景、转场素材这类「量大、要求低、云端按秒计费很亏」的部分
- ⚠️ 风险：**876 个 open issue 对 4,921 stars 的比例很差**，说明用的人多但维护跟不上，遇到问题大概率要自己看源码；8GB 是最低档，速度与画质都要降级，「能跑」不等于「能用」；本地省的是 API 钱，花的是电费和时间——一张 4060 Laptop 跑一条 10 秒片子的时间，够云端跑几十条，**先用它做草稿、别用它做交付**
- 源：GitHub FlashML-org/FreeVideo 与 README（11/25 实测 star / fork / issue / 许可证 / 建仓时间，含 v0.4.0 与 v0.5.0 changelog）

**sous-labs/songe（主推·拿你的空闲算力训练你自己的本地模型，数据不出机器）**
- 是什么：一个 `pip install songe` 就能装的训练引擎。你用 opencode、pi 或任何 OpenAI 兼容工具正常调本地模型，它在旁边记录「模型每个动作之后实际发生了什么」——工具返回什么、报了什么错、你下一句怎么改。等 agent 空闲了，它把这些变成课教给你的模型。**739 stars、64 forks、24 个 open issue、Python、Apache-2.0、2026-11-20 建仓（5 天）、11/25 最后提交**
- 差异化：绝大多数「让模型记住你」的方案是往 prompt 里塞上下文，它走的是另一条路——**两种 Dream**：Quick Dream 几分钟内把你的偏好写进模型指令；Deep Dream 在你离开时真的训练权重。关键是它的验收标准：**新版本只有在「你自己的历史对话」上表现更好才会被启用，一键可回滚到任一旧版本**。这个设计比「个性化」本身更重要，它把「训练」变成了可回退的操作。无账号、无遥测、无云
- 用在哪：你每天在做的「剧本打标 / 分镜描述 / 投放文案改写」里有大量**你反复纠正同一件事**的情况（比如命名习惯、口径写法、禁用词）。把这些纠正攒下来，让它替你记住，比每次在 prompt 里写一遍规则省事。另一个用法是给它接一个本地 7B–14B 量化模型专门干「格式转换、字段抽取」这类脏活，越用越贴合你的表格结构
- ⚠️ 风险：**建仓只有 5 天、739 stars，属于极早期**，Deep Dream 的实际效果没有任何第三方复现；「数据不出机」是项目自述，代码可读但不等于已审计；Deep Dream 需要真训练，你这台 16GB 内存的机器只够跑小模型的小适配器，别指望它把 32B 训成专家；它只在你空闲、内存足、电量够时跑——意味着笔记本上它可能永远等不到窗口
- 源：GitHub sous-labs/songe 与 README（11/25 实测 star / fork / issue / 许可证 / 建仓时间，含 PyPI 页面与 ROADMAP）

**mankidev/antialgorithm（备选·让模型先说出它最平庸的那个选择，然后走开）**
- 是什么：一个 agent skill，装法是一行 `npx skills add mankidev/antialgorithm`，或克隆到 agent 的 skills 目录（Codex、Cursor、OpenCode、Claude Code 等通用）。它的机制很具体：**先让模型明确说出它「第一个、最平均」的选择，然后基于项目本身的理由往反方向走**。README 里用一组对照图说明——同一个「设计一个音乐节海报 400×600 SVG」的提示词，不用技能的一批 6 张全在中位数附近，用了技能的那批明显分化。**842 stars、53 forks、0 个 open issue、MIT、2026-11-14 建仓、11/20 最后提交**
- 差异化：几乎所有 agent skill 都在教模型「做得更多/更规范」，它教模型「别选第一个想到的」。这个方向对创意类任务有效，因为模型的默认输出天然是**分布的中位数**——最安全、最像训练数据里的平均值
- 用在哪：短剧的**命名、标题、海报文案、封面构图、UI 配色**。你先用默认模型出一批，记下那种「都对但都不想点」的感觉；装上它再出一批，对比差异。更实际的用法是**给选题会用它做发散**：让模型给出 10 个方向，其中至少 3 个必须偏离它自己说的「平均值」
- ⚠️ 风险：**建仓 11 天、0 个 open issue**——不是没 bug，是还没被压力测试过；创意好坏没有客观指标，别用它「评估」效果，它只影响发散阶段；这类「反向指令」在不同模型上效果差异很大，README 的对照图是自己项目写的技能跑了约十几次挑出来的，存在挑选偏差
- 源：GitHub mankidev/antialgorithm 与 README（11/25 实测 star / fork / issue / MIT / 建仓时间，含官方对照图与安装命令）
