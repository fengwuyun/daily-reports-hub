**2. Cursor 扩展市场被投毒：恶意 Claude Code 扩展偷 SSH 密钥，约 5000 用户中招（P0·跟你工具链直接相关）**

⚠️ 行动项：装过这两个版本的，先 grep 一下自己 authorized_keys 有没有 svc-telemetry；扩展只从官方 Marketplace 装，第三方市场默认不可信。你自己跑着 Claude Code / Codex，这一条照做。

**3. 恶意软件开始用 Claude 给受害者「估价」再定攻击力度（P2·安全）**

## 四、小而美产品

**Hexis（主推·跟你本机 agent 权限分层直接相关）**
- 是什么：Bevel Software（UTCP 协议团队）的开源核心，Apache-2.0、TypeScript——把 AI agent 的技能、工具定义、上下文、权限、身份放进一个 git 仓库统一管理，Docker 自托管，同时暴露 MCP 服务器（OAuth 2.1）和 UTCP 直调双协议
- 差异化：agent 提案可以自动同步、但只有人能 merge；工具更新 10 秒内热生效不用重连；每个连接密钥可审计「谁、什么时候、调了什么」。等于给你的 agent 装了个带审批卡点的控制面
- 用在哪：你本机跑着能碰飞书/邮箱/文件的自动化，参照币安案教训，把工具权限按「只读/可写」分角色发密钥，改动走 git 审计
- ⚠️ 团队是创业公司不算严格独立开发者；Windows 上需 Docker；2026 年 9 月首发 0.19，版本尚早
- 源：GitHub / 官方文档，2026-09~10

**SuperLocalMemory（主推·开源 agent 记忆层）**
- 是什么：PH 10 月末新品，「governed memory brain for every AI agent」——给 coding agent 提供带治理的本地记忆库，开源
- 差异化：切中 agent 记忆最被抱怨的两个点——跨项目记忆污染、记了不用衰减。本地优先，数据不出机器
- 用在哪：你多项目并行跑 Codex/WorkBuddy 时，按项目隔离上下文记忆，避免 A 项目的笔记串进 B 项目
- ⚠️ 新品，具体实现（存储格式、接入方式）、Windows 兼容未实测，先小项目试用
- 源：Product Hunt 新品榜，10 月末
